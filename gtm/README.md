# OpenField Go-To-Market（GTM 计划）

> 版本 V0.1 草案 · 2026-09-12。按 GTM 最佳实践的完整骨架组织：主论题 → 市场与时机 → 目标用户 → 定位与信息 → 商业模式 → 渠道与内容 → 分阶段发布 → 漏斗与北极星 → 指标 → 风险与红线。
> 产品现状见 [README](../README.md)；需求源与收益线见 [CAMPAIGN](../docs/研究/行动总纲.md)；一切增长的底线见 [PRINCIPLES](../PRINCIPLES.md)。定价与转化率均为**待验证假设**，本文不作交付承诺。

## 0. GTM 主论题（Thesis）

OpenField 的 GTM 不是「卖软件」，而是**把方法论变成影响力，把影响力变成生意**：

1. 创始人背着 OpenField 完成真实田野（PRINCIPLES §5 创始人田野法则）→ 产出证据级内容：纪实 Vlog、田野日志、研究报告；
2. 内容建立「AI 田野调查」品类与真名 IP → 同时吸引三类人：**研究者**（用产品）、**企业**（买咨询）、**观众**（进社群）；
3. 产品核心永久免费开源以建立信任，服务与后续高级能力变现——对齐 CAMPAIGN 的五条收益线。

与常规 SaaS 的最大差异，写在第一页：

> **受访者数据永不用于增长**（PRINCIPLES §6 非目标）。营销素材只能来自「方法与过程」——怎么进现场、怎么访谈、怎么存证；绝不来自「数据与内容」——受访者说了什么。每一篇对外内容发布前过一遍[伦理自查清单](../docs/工程/伦理自查.md)第 5 节的镜像检查。

## 1. 市场与时机

**市场缺口（按工具类型）：**

| 现有工具 | 解决了什么 | 没解决什么 |
| --- | --- | --- |
| NVivo / MAXQDA / ATLAS.ti | 编码与分析 | 采集与存证薄弱；授权昂贵；学术预算外个人难承受 |
| 转写 / 会议工具（讯飞、Otter 类） | 「听清」 | 「可信」：无防篡改、无引用、数据默认上云 |
| 通用笔记（Notion / 飞书 / Obsidian） | 灵活记录 | 无方法论约束、无证据链、无伦理流程 |
| 纸笔 + 手机录音（田野现状主流） | 零门槛 | 材料散乱、无法溯源、难以应付评审与合规质疑 |

**中国语境的空档**：PIPL 合规、学术伦理审查对知情同意存证的要求、县域乡村的离线场景——国外工具普遍覆盖差；OpenField 从第一天就为此设计。

**为什么是现在**：AI 生成内容泛滥，使「可验证的一手材料」成为稀缺资产——谁能为结论出示证据，谁就有差异化；同时 AI 让「分析」平民化，行业竞争焦点正从「怎么分析」移向「材料从哪来」。OpenField 卡位的是上游：**采集与存证**。

## 2. 目标用户（ICP 分层）

| 层 | 人群 | 核心痛点 | 首选价值 | 阶段 |
| --- | --- | --- | --- | --- |
| T0 | 创始人本人 | 真实田野需要趁手工具 | Dogfood：一切设计的第一个用户 | 现在 |
| T1 | 质性研究者：社会学/人类学/新传的研究生与博士、UX 研究员 | 录音、笔记、照片散落多处；引用无法溯源；同意书难管理；分析软件贵 | 证据链 + 引用 ID + 一体化田野档案 | Phase 1–2 |
| T2 | 田野型创作者：记者、非虚构作者、独立调研者 | 一手素材的可信度就是差异化，但无法自证 | 「我拍了哈希」级别的素材可信度叙事 | Phase 2 |
| T3 | 咨询与企业洞察团队、国际研究者 | 需要团队协作、合规审计 | 协作与机构能力（P2+，假设） | Phase 3+ |

**两个种子画像**（Phase 1 私测招募对象）：

- 「方法课的博士生」：正在准备田野，导师要求伦理材料齐全，预算有限，会用 GitHub 但不是开发者；
- 「UX 研究员」：每月做用户访谈，录音散在手机和电脑，被合规部门问起「数据存哪」时无法回答。

## 3. 定位与信息

**定位声明**（Geoffrey Moore 式）：

> 对于**需要一手材料支撑结论、且结论要经得起评审或甲方质疑的中国质性研究者与田野型创作者**，OpenField 是一套可随身携带的田野调查操作系统。不同于 NVivo 类软件（重分析、轻采集、价格高），不同于云转写工具（只转不证），也不同于通用笔记（无方法论约束），OpenField 从采集瞬间就固化证据链、整库本地加密，并把研究伦理内置为流程——**让现实留下可查证的回执**。

**信息屋（Messaging House）：**

```
                主信息：Grounding AI in Human Reality
                让 AI 扎根于人的真实经验
┌──────────────────────┬──────────────────────┬──────────────────────┐
│ 支柱 1 证据级严谨      │ 支柱 2 为田野而生      │ 支柱 3 AI 是同事       │
│ 哈希链 + 只读封存      │ 离线优先 + 极简采集    │ 只提案、人工确认       │
│ + 可引用到秒的 RefId  │ + 中国语境伦理（PIPL） │ + 换模型不换底线       │
│ 证据：开源可校验的代码 │ 证据：县域无网可用设计 │ 证据：P1 刻意不接 AI   │
└──────────────────────┴──────────────────────┴──────────────────────┘
```

**竞争叙事**：不打「更好的 NVivo」——分析是 P3 的事。打「NVivo 拿到的材料是口头保证，OpenField 拿到的材料是数学保证」。对转写工具的叙事：转写解决「听清」，OpenField 解决「可信」，前者可以成为后者的输入（外部转写文本是一等公民，见[架构](../docs/工程/架构.md) §5）。

## 4. 商业模式与包装

原则：**信任先于收入，核心能力不上收费墙**——证据链、加密库、引用、清除这些「宪法能力」永久免费开源（MIT）。

| 收入层 | 内容 | 对齐 CAMPAIGN 收益线 | 时点 |
| --- | --- | --- | --- |
| 咨询与交付 | AI 落地诊断 + 田野研究方法服务 | 线 1（咨询收入） | 最先启动，现在 |
| 内容收入 | 平台激励、商单 | 线 3（自媒体） | Phase 0 起 |
| 知识付费 | 田野方法专栏/课程（语料库是天然教材） | 线 4（知识付费） | Phase 2 |
| 社群 | 同路人社群（研究者 + 创作者） | 线 4 | Phase 2–3 |
| 产品高级层（假设，待验证） | E2E 加密云同步（opt-in）、团队协作、机构版 | 线 5（IP 溢价的延伸） | P2 之后单独论证 |

定价不在此阶段承诺；任何收费动作前先跑 Phase 1 的支付意愿访谈。

## 5. 渠道与内容策略

主渠道是**创始人的田野内容飞轮**（build in public），产品、内容、咨询三条线互为燃料：

**平台矩阵（中文先行，PRINCIPLES §4）：**

| 平台 | 角色 | 内容形态 |
| --- | --- | --- |
| B 站 | 主阵地 | 纪实 Vlog：田野全程、被拒、失败、认知颠覆 |
| 小红书 | 方法卡片 | 「怎么设计访谈提纲」「同意书怎么签」可收藏卡片 |
| 公众号 | 深度复盘 | 田野日志全文 + 产品日志 |
| 知乎 | 学术信任 | 质性方法问答，引用语料库正文 |
| GitHub | 开发者/学术信任 | 开源仓库、CITATION.cff、issue 公开 |
| 视频号 | 私域沉淀 | 短内容引流至社群 |

**内容三板斧**（每条内容必须落到其中一类）：

1. **田野纪实**——过程与失败本身（CAMPAIGN §7.2 的蓝海定位）；
2. **方法拆解**——把 [fieldwork 语料库](../docs/田野方法/README.md)拆成可消费的单篇；**语料库 + [模板包](../docs/田野方法/11-模板.md)本身就是 lead magnet**，已存在、可直接分发；
3. **产品日志**——一个功能 = 一个真实田野问题（如「为什么收件箱拒绝空文件」讲 iCloud 占位符）。

**学术渠道**：方法课与工作坊合作、论文引用（CITATION.cff 就绪）、高校社团分享。学术采用是最慢但最深的护城河。

## 6. 发布计划（四阶段 + 闸门）

每阶段以**闸门**收口，闸门不过不进下一阶段——用工程纪律管发布：

| 阶段 | 动作 | 闸门（exit criteria） |
| --- | --- | --- |
| **P0 验证期**（现在 → P1 完） | 创始人真实田野 dogfood；每周开发/田野日志 | 一次完整田野行程全程使用 OpenField（采集→入库→校验→引用走通） |
| **P1 私测期** | 招募 10–30 名 T1 种子用户（方法课学生、UX 研究员）；waitlist 收集；每两周一次用户访谈 | 种子用户各自完成 ≥3 次真实田野任务；口令/备份/还原无致命卡点 |
| **P2 公测期** | 公开下载；内容飞轮全开；模板包与语料库公开分发 | 周活跃田野用户（见 §7）连续 4 周增长；内容矩阵至少一个平台跑出代表作 |
| **P3 正式期（1.0）** | 「经田野验证」版本发布；机构试点；评估国际化启动 | 1.0 达成 PRINCIPLES §5 全部质量基准；付费假设完成至少一轮真实报价测试 |

## 7. 漏斗与北极星

漏斗用田野语言命名，每步都可度量：

```
触达（内容曝光）→ 进场（GitHub 访问 / 下载）→ 入场（创建 vault）
  → 首猎（完成首次田野任务：登记事件+访谈+入库≥1 件+校验通过）
  → 回场（次周仍有田野任务 = 留存）→ 引荐（分享模板 / 引用 ID / 内容）
```

**北极星指标：每周「带证据链的真实田野任务」完成数。**

选它的理由：与 PRINCIPLES §5 的「任务完成率」同源——必须真实走到田野才能产生，无法用增长黑客手段刷量；同时它直接度量产品核心价值（采集→存证闭环）而非虚荣数据。

**反向指标（明确不追求）**：注册数、PV、下载量——它们是结果不是目标，且可被污染。任何以牺牲北极星为代价换这些数字的动作，违反宪法气质，不做。

## 8. 指标体系

| 维度 | 指标 | 阶段 |
| --- | --- | --- |
| 北极星 | 每周带证据链的田野任务完成数 | 全程 |
| 产品激活 | 下载 → 创建 vault → 首猎的转化率；次周回场率 | P1 起 |
| 产品健康 | 用户校验通过率；备份导出渗透率（有备份的用户占比） | P1 起 |
| 内容 | 各平台播放/完播/粉丝；内容 → GitHub 进场归因 | P0 起 |
| 学术 | 语料库/模板被课程采用数；CITATION 被引数 | P2 起 |
| 商业 | 咨询线索数、转化数（对齐 CAMPAIGN §5.1 KPI） | 全程 |
| 质量护栏 | 确认合规（P0 缺陷为零）；未田野验证版本必须标注 | 全程（PRINCIPLES §5） |

## 9. 风险与红线

| 风险 | 应对 |
| --- | --- |
| **伦理红线（最高优先）** | 不用受访者数据做增长；对外案例先脱敏并取得单独授权；绝不演示任何形式的隐蔽采集；「取证」话术只说防篡改，**不宣称司法鉴定效力** |
| 合规边界 | PIPL 叙事聚焦「受访者权利」（删除权、撤回），不越界承诺合规认证 |
| 竞品反压（NVivo 生态、转写工具下沉） | 不正面竞争：卡位上游「采集-存证」；转写工具定位为输入源；学术合作优先于对抗 |
| 单人节奏（内容断更、功能跳票） | 最低节奏承诺：每周至少一条内容；以 CAMPAIGN §8.4 的 Kill Switch 纪律管理整体投入 |
| 平台风险（单平台限流/封号） | 一鱼多吃：一次田野素材多平台分发；GitHub 是不依赖任何平台的自有阵地 |
| 定价假设落空 | 高级层收入是 P2 后假设；若支付意愿测试失败，回退「纯服务 + 开源」模式——CAMPAIGN 五条线中前三条不依赖软件收费 |
