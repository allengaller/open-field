# OpenField 桌面端使用手册

> 版本 V1.2 · 2026-09-12 · 对应当前 P1 桌面端（Cobalt 工作台，五视图 + 演示数据 + 合规清除全接入）。界面为单窗口应用，左侧栏切换视图；底部状态栏常显锁定状态与数据目录；每个操作的结果以等宽读出行显示在内容区顶部，错误红字 + 右下角 toast。
> 技术实现细节见 [ARCHITECTURE](架构.md)；方法论背景见[田野调查语料库](../田野方法/README.md)。

## 0. 开始之前，三条铁律

1. **口令丢失无找回。** vault 是真实加密，没有后门。口令请抄写在纸上、与备份分开放置。
2. **整盘加密是使用前提。** 原始件（录音/照片）在磁盘上只读封存但未逐文件加密——请先开启 FileVault（系统设置 → 隐私与安全性 → 文件保险箱），再使用本系统。
3. **同意先于采集。** 系统不阻止你，但方法论与伦理要求你：任何录音/拍照前，先取得受访者知情同意并录入系统。见 [07 伦理](../田野方法/07-伦理.md)。

## 1. 环境与启动

```bash
# 要求：Node ≥ 22，pnpm 11（corepack enable）
pnpm install

cd apps/desktop
pnpm dev      # 启动桌面应用（开发模式）；pnpm build && pnpm e2e 可跑完整验证
```

想先看效果不建真实库？解锁后到「总览 → 演示数据 → 载入演示数据」，见 §3.6。

默认数据目录在系统用户数据目录（Electron userData）下。开发或多库场景建议显式指定：

```bash
pnpm dev -- --openfield-home=~/openfield-kunming
```

数据目录布局（首次建库后自动创建）：

```
<home>/
├─ vault.db        # 加密资料库（所有结构化数据的唯一权威）
├─ originals/      # 原始件只读封存 originals/<采集物ID>/v1.<ext>
├─ inbox/          # 导入暂存——把录音/照片丢进来（持续监视）
├─ quarantine/     # 畸形 bundle 隔离区（一般不碰）
└─ backups/        # 加密备份输出
```

> iCloud 用户：把 iCloud 同步的某个目录（如 `~/Library/Mobile Documents/com~apple~CloudDocs/` 下的录音目录）用符号链接指向 `inbox/`，手机录音回流后自动进入待办。

## 2. 核心概念（2 分钟版）

| 概念 | 是什么 | 例子 |
| --- | --- | --- |
| FieldEvent 田野事件 | 一次田野活动（半天/一天） | `evt-1`：2026-09-11 在昆明篆新市场 |
| Encounter 访谈 | 事件中的一次交流/访谈 | 受访者 P-001，目的性抽样 |
| Participant 受访者档案 | 仅化名 + 行业/地区/**引荐链**/同意范围 | P-001，水产摊主，昆明 |
| ConsentRecord 知情同意 | 录音/肖像/发表三类，可撤回 | consent-xxx：仅用于学术研究 |
| Artifact 采集物 | 录音/照片/笔记/文档，哈希封存 | interview.wav |
| InboxItem 待办 | inbox/ 里等你确认归属的文件 | 待确认 → 入库 |
| RefId 引用 ID | 永久可引用编号，一经签发不可变更 | `OF-20260911-KMG-001#T12:34` |
| Memo 备忘录 | 田野日志/反身性/分析草稿，人工确认后入链 | journal-2026-09-11 |
| EvidenceEntry 链条目 | append-only 哈希链，全链可查看 | 每一条写操作都留痕 |

工作流总览：

```
登记事件 → 登记录音/访谈 → 建档受访者 + 记录同意 → 文件投进 inbox/
→ 扫描 → 确认入库 → 校验 → 签发引用 → （每日）生成日志 → 备份
→ （受访者要求时）PIPL 单人全链路清除
```

## 3. 分步操作（按视图）

### 3.1 总览：资料库 / 时间同步 / 备份 / 演示数据 / 危险区

- **建库 / 解锁**：输入口令（≥ 8 字符）点「创建资料库」或「解锁」。顶部计数（事件 / 访谈 / 待入库）随之刷新，侧栏锁定芯片与底部状态栏显示 `UNLOCKED / LOCKED`；「刷新状态」重新读取。读出行显示完整状态 JSON（机器读数，即 e2e 断言格式）；
- **时间同步**：`NTP 校时`，偏移量以 `TIME_SYNC` 条目入链——「采集时刻被改过」事后可检出。离线田野属预期：同步失败会给出明确提示，本机时钟仍用于日常操作；
- **备份导出**：以口令输入框中的口令加密打包（OFBK1 容器：scrypt + AES-256-GCM，加密库副本 + 全部原始件），完成后读出行显示备份路径；同名文件已存在会拒绝，不静默覆盖。还原流程 UI 尚未提供（底层 `readBackup` 已实现），当前以「整目录拷贝 `<home>/`」迁移。纪律：**每次田野日结束备份一次**，3-2-1 原则；
- **演示数据**：一键载入/清除一套可编辑的示例田野数据（3 事件 · 5 受访者 · 5 访谈 · 6 采集物 · 同意书 · 备忘录 · 2 条待办收件），用于熟悉全部功能。内容在 `apps/desktop/src/main/services/mock-data.ts` 中定义，可随意修改。载入全部走真实入库路径（哈希链可校验）；清除只删演示行与文件，证据链日志按 append-only 铁律保留。标签芯片实时显示当前载入规模；
- **危险区 · PIPL 删除权**：输入受访者笔名并**再次输入同一笔名**确认（两次必须完全一致），即可不可逆清除 TA 的全部访谈、同意书、采集物文件、关联备忘录与真名映射；清除事实与范围以 `PURGE_SUBJECT` 条目永久留痕（不含内容）。此操作无法撤销，见 §3.7。

### 3.2 采集登记：事件 / 访谈 / 受访者建档 / 知情同意

四个面板自上而下：

- **事件**：编号、日期（`2026-09-11`）、城市码（**恰 3 位大写字母**，如 `KMG`）、地点名称、可选**背景注记**（开市时段、摊位分布等现场背景）。编号重复会被拒绝；
- **访谈**：编号、所属事件编号（不存在会被拒绝）、**受访者笔名**（如 `P-001`——**绝不填真名**）、**为何选 TA**（抽样逻辑本身即研究资料）、可选备注（现场情况、语言、氛围）；
- **受访者建档**：笔名 + 行业/身份 + 地区 + **引荐链**（谁把 TA 介绍给你，按顺序逗号分隔，如 `P-001, P-002`——滚雪球抽样的证据）+ **同意范围**勾选（录音/肖像/发表）。笔名已存在则更新档案；建档与每份材料一样入链（`CREATE_PARTICIPANT`）；下方另有**真名映射**输入——仅写入加密库独立表，分析层不可见、不入证据链，受访者行使删除权时随清除一并销毁；
- **知情同意**：访谈编号 + 同意类型（录音/肖像/发表）+ 范围说明（如「仅用于学术研究」「照片可用于论文插图」）。每份同意书单独留痕（`CONSENT_RECORDED`）；**撤回**在档案库的访谈详情中操作（见 §3.5），撤回后引用门禁即刻生效。

### 3.3 收件箱：导入与确认

把文件放进 `inbox/`（手动拖入，或链接 iCloud 同步目录），watcher 自动发现，点「扫描」刷新列表：

- 支持格式：`wav / mp3 / m4a / aac`（音频）、`jpg / jpeg / png / heic`（照片）、`pdf / docx`（文档）、`txt / md`（笔记）。**其他扩展名拒绝入库**——系统不猜测证据类型；
- 空文件与 iCloud 占位文件（`.xxx.icloud`）自动跳过；同一文件重复投放只登记一次（按 SHA-256 去重）；
- 每条待办显示文件路径，若扫描时按日期推断出**建议归属**（`建议归入 enc-…`）会标出；
- 两个动作：「确认入库」（先填归属访谈编号——留空且有建议归属时自动采纳——文件随即哈希封存、写入证据链，**采集物 ID 自动填入证据链页的引用输入框**）与「忽略」（标记为 rejected）；
- 手机端 bundle（`*.ofbundle.json`）自动应用；格式错误的进 `quarantine/`，不污染主库。

### 3.4 证据链：校验 / 链日志 / 引用

- **校验**：点「运行校验」生成报告，芯片显示 `CHAIN OK` 或 `ISSUES`。`"chainOk": true` = 证据链完好，`"issues": []` = 原始件全部在位且哈希一致。四类问题：`hash-mismatch`（被改/损坏）、`original-missing`（缺失）、`orphan-directory`（未登记目录）、`unreadable`（不可读）；
- **链日志**：EVIDENCE LOG 面板逐行显示全部链条目（序号 / 时间 / 动作 / 操作者 / 哈希前缀）——「这份录音从未被修改过」的证明就在这里，随时可查。条目只增不改，任何对历史记录的篡改都会在下次校验时现形；
- **引用**：输入采集物编号点「生成引用」，生成形如 `OF-20260911-KMG-001#T12:34` 的永久引用（精确到录音内某一秒），点「复制」进剪贴板。**同意门禁**：audio 需未撤回的录音同意、photo 需未撤回的肖像同意，缺失会被拒绝并提示先记录同意书（doc/note 不受限）——采集与封存永不拦你，但可被引用的材料必须过得了同意这道关；引用**一经签发永不变更**（重复生成幂等返回同一 ID；序号只增不复用——PIPL 清除后，已发表材料的编号也不会再分配给别的材料）；论文引用时附上对应 sha256，审稿人可验证材料未被改动。

建议节奏：每次收工前校验一次；换机/迁移后必校验。

### 3.5 档案库：三级浏览 + 访谈详情 + 田野日志

- **三级下钻**：事件 → 访谈 → 采集物，自左向右逐列点击。点击访谈后，底部展开**访谈详情**三栏：
  - **受访者**：笔名 + 行业 + 地区 + **引荐链**（`P-001 → P-002`，种子受访者标注「无引荐」）；
  - **知情同意**：每份同意书以芯片显示类型（录音/肖像/发表）与范围说明，撤回的以红色「已撤回」标出；**未撤回的同意书带「撤回」按钮**——点击后 `CONSENT_WITHDRAW` 入链，该访谈的录音/照片即刻失去引用资格（门禁生效）；
  - **备忘录**：反身性 / 分析 / 田野日志草稿，未确认的带「确认入档」按钮——点击后 `MEMO_CONFIRM` 入链，状态变为「已确认」。**AI 只提案、你确认**的闭环在此；
- **生成当日田野日志**：自动聚合**当天**的事件/访谈/采集物为草稿备忘录（补写反思由你自己来），再次点击相同日期幂等不重复；
- 「刷新档案」重新加载；每列为空时有指引文案。

### 3.6 演示数据（快速体验全部功能）

「总览 → 演示数据 → 载入演示数据」：

- 含：3 个田野事件（昆明篆新市场 / 木水花菌市 / 大理古城早市）、5 位受访者（含两跳滚雪球引荐链）、5 条访谈（覆盖便利/目的性/滚雪球抽样）、6 份采集物（录音/照片/笔记，**真实封存可校验**）、6 份同意书（含 1 条已撤回）、备忘录（反身性/分析草稿 + 每事件日期的田野日志）、2 条待办收件、1 条已签发引用；
- 载入后可完整走一遍：收件箱确认入库 → 档案库查看详情 → 备忘录确认 → 校验（`chainOk: true`）→ 引用/复制 → 危险区清除某位受访者验证 PIPL 流程；
- **如何修改**：编辑 `apps/desktop/src/main/services/mock-data.ts`（文件头有注释），任何结构都对应一个可见功能；改完回到应用重新「载入」（先清后载，幂等）；
- **清除语义**：只删演示业务行与封存文件；证据链日志保留（append-only 铁律——链上记录的是「这些登记发生过」的事实，不可也不应抹除）。

### 3.7 PIPL 删除权（危险区操作细节）

受访者要求删除数据时（《个人信息保护法》第 47 条）：

1. 在「危险区」填入受访者笔名；
2. 在确认框**再次输入同一笔名**（防误触；不一致会被拒绝并提示）；
3. 点「清除该受访者全部数据」——执行后读出行报告清除范围（访谈 / 同意书 / 采集物 / 备忘录计数），原文件销毁，`PURGE_SUBJECT` 入链留痕。

**不可撤销。** 执行前请与受访者确认删除范围；清除后该校验报告中的 `original-missing` 属于正常残留提示（文件已按意愿销毁）。

## 4. 常见问题对照

| 现象 | 原因与处置 |
| --- | --- |
| 「vault 口令错误或文件已损坏」 | 口令输错，或文件真的损坏。无找回——找备份 |
| 「vault 未解锁」 | 先建库/解锁 |
| 「无法识别的扩展名」 | 格式不在支持列表；转成支持格式，或先记笔记描述该材料 |
| 「空文件拒绝登记」 | iCloud 占位文件未下载完成：在访达里点一下让它下载完 |
| 扫描后待办没有出现 | 文件之前投过（同路径已 pending/ingested）；或 vault 未解锁 |
| 「该访谈尚无有效知情同意…」 | 引用门禁拦截：录音需 recording、照片需 portrait 且未撤回。到「采集登记 → 知情同意」为对应访谈补记，或确认是否已误撤回 |
| 校验报 `original-missing` | 文件被移动/删除，或刚执行过 PIPL 清除（属正常残留报告）。否则从备份恢复 |
| 「时间同步失败」 | 离线或 NTP 不可达——田野常态，本机时钟仍可用，回城后再同步 |
| 演示数据载入后校验报错 | 先确认没有混入真实数据（演示与真实数据同库共存是设计内的）；清除演示数据后再看 |
| 载入演示数据时提示重复 | 不会发生——载入先清后载幂等；如确有报错，先「清除演示数据」再载入 |
| bundle 待办反复出现 | 该 bundle 的 mediaRef 尚未确认入库；确认后不再出现 |

## 5. 纪律（系统管不了的部分）

系统保证：登记过的材料不丢、不改、可验证、可删除。系统不能保证：

1. **你记得备份**——唯一的防线是你的备份节奏；
2. **口令不写在备注里**——写在纸上，别在云端备忘录；
3. **真名不进化名字段**——录入时自觉；`participant_identity` 表只在确需对应时使用（分析层默认不见真名）；
4. **真实田野数据不进这个代码仓库**——issue 截图、测试数据一律用演示/合成数据（[CONTRIBUTING](../../CONTRIBUTING.md) 红线）；
5. **田野里的判断**——同意、退场、对方情绪，都在你不在软件里。见 [行动总纲](../研究/行动总纲.md) 的风控清单与 [07 伦理](../田野方法/07-伦理.md)。
