# OpenField 威胁模型（Threat Model）

> 版本 V1.0 · 2026-09-12 · 覆盖 P1 桌面端已实现现状，与 [ARCHITECTURE](架构.md) 同步演进。
> 本文档回答三个问题：我们在保护什么、防谁、现在防到什么程度。漏洞报告渠道见 [SECURITY](../../SECURITY.md)；伦理边界见 [PRINCIPLES](../../PRINCIPLES.md) §2.4。

OpenField 存放的是证据级田野数据。此处的威胁模型不是形式：资料库里是真名、录音、同意书——泄露的对象是活生生的人。

---

## 1. 资产（按敏感度排序）

| 资产 | 位置 | 泄露后果 |
| --- | --- | --- |
| **受访者真名映射** | vault.db 的 `participant_identity` 表 | 受访者可被去匿名化——最高级别损害，可能导致现实伤害 |
| **录音 / 照片 / 文档原始件** | originals/ + vault.db 登记记录 | 言论被溯源；受访者遭报复 |
| **知情同意记录** | vault.db | 同意范围被篡改 = 学术伦理灾难 |
| **证据链（evidence_log）** | vault.db | 被篡改 = 研究结论失去可验证性 |
| **田事件/访谈元数据** | vault.db | 抽样逻辑、人员关系、行踪模式暴露 |
| **加密备份（.ofbackup）** | backups/ 及导出后的任意位置 | 等同于 vault 本体（口令强度成为唯一防线） |
| **收件箱/隔离区暂存文件** | inbox/, quarantine/ | 导入前的明文窗口期 |

## 2. 对手（Adversaries）

| 对手 | 能力 | 动机 |
| --- | --- | --- |
| **设备扣押 / 边检** | 长时间物理持有设备，可离线穷举 | 获取录音内容与受访者身份 |
| **设备丢失 / 窃取** | 物理访问磁盘 | 同上（机会主义） |
| **同住 / 同行者** | 短暂物理访问、复制文件 | 好奇、恶意、被迫交出 |
| **本地恶意软件** | 以用户权限读写文件系统与剪贴板 | 商业窃密、定向监控 |
| **网络路径攻击者** | 可观测/篡改出站流量 | 流量分析（OpenField 几乎不出站） |
| **供应链** | npm 依赖、Electron 本身的投毒 | 大规模横向 |
| **研究者自己的失误** | 一切操作权限 | 误删、误提交真实数据到公开仓库 |

明确**不在**对手列表内（非目标）：对受访者或第三方的隐蔽监控——OpenField 永不支持隐蔽采集，相关能力请求视为漏洞对待。

## 3. 攻击面与缓解措施（As-Built）

| 攻击面 | 缓解措施 | 状态 |
| --- | --- | --- |
| 磁盘被获取 → 资料库 | vault.db 整库 SQLCipher 加密；口令 ≥ 8 字符；错误口令在首次读取即暴露 | ✅ 已实现 |
| 磁盘被获取 → 原始件 | chmod 0444 只读封存（**防改动，不防读取**） | ⚠️ 残余风险 §5.1 |
| 篡改研究记录 | 哈希链 append-only：应用层无 UPDATE/DELETE 路径 + 库层触发器 `RAISE(ABORT)`；verify 全链重放 | ✅ 已实现 |
| 篡改原始件 | 采集时哈希固化 + 封存后二次校验 + verify 逐一重算 | ✅ 已实现 |
| 删除原始件 / 勒索 | VACUUM INTO 加密备份 + OFBK1 全量容器 | ✅ 已实现（备份纪律靠使用者，§5.5） |
| 渲染层被攻破（XSS → 系统权限） | `sandbox: true`、`contextIsolation`、无 `nodeIntegration`；IPC 通道白名单；所有入参 zod 校验 | ✅ 已实现 |
| SQL 注入 | 参数化查询全覆盖；动态表名仅限字面量调用方（防注入约定见 repos.ts） | ✅ 已实现 |
| 借 artifact id 路径穿越删除 | purge 删除前 `relative()` 围栏校验，越界即拒绝 | ✅ 已实现 |
| 误触发破坏性操作 | purge 需 confirmToken === pseudonym 的显式确认；备份目标已存在即拒绝（不静默覆盖） | ✅ 已实现 |
| 删除操作不留痕 | 清除事实与范围以 `PURGE_SUBJECT` 入链（不含已删内容）——「清除」本身可审计 | ✅ 已实现 |
| 时间造假掩盖篡改 | NTP 校时偏移以 `TIME_SYNC` 入链 | ✅ 已实现（有前提，§5.3） |
| 依赖投毒 | 版本钉死 + pnpm lockfile + CI `--frozen-lockfile` | ✅ 基线（供应链纵深属持续工作） |
| 真实数据误入公开仓库 | 贡献红线（CONTRIBUTING）+ 测试夹具只允许合成数据；E2E 用临时目录与假字节 | ✅ 流程约束 |
| 设备丢失后的远程处置 | 依赖操作系统「查找」能力（Find My），不自建 | ⚠️ 系统级，非应用级 |

### 出站网络清单（完整）

P1 桌面端唯一的对外流量是 NTP 校时（UDP，默认 `ntp.aliyun.com`）。无遥测、无上传、无自动更新检查、无任何同步——联网与否则完全由使用者控制，云端同步在 P1 不存在。

## 4. 关键安全设计决策（Why）

1. **口令无找回**：证据系统的加密是真实的加密——有找回就有后门。首启动须知里明示，这是「证据链系统的合理代价」（架构规格 §5）。
2. **真名边界在类型层强制**：core 的 `Participant` 是 strictObject，携带 `real_name` 字段直接解析失败——不是靠约定，是靠类型系统让违规代码无法编译通过。
3. **先删文件、后删记录**：purge 若中途失败，宁可留下「隐私已消失、登记残留」（verify 可见报告），绝不留下「文件还在、DB 删了一半」——两种失败模式里，前者只损失整洁，后者泄露隐私。
4. **校验失败必须可见**：verify 对「目录不可读导致孤儿检查未执行」单独出 issue，而非静默跳过——安全报告里的静默就是漏洞。
5. **拒收优先于猜测**：无法识别的扩展名拒绝入库（拒绝猜测证据类型）、空文件拒收（iCloud 占位）、畸形 bundle 进隔离区——导入路径上宁可漏，不可错。

## 5. 残余风险（诚实清单）

接受或缓解前，这些风险**真实存在**：

1. **原始件磁盘明文**：originals/ 的文件本身未加密（只读 ≠ 加密）。**使用前提：整盘加密（macOS FileVault）必须开启**，否则「资料库加密、原始件裸奔」。逐文件加密列入候补路线。
2. **口令强度由人决定**：≥ 8 字符是下限不是安全线。离线穷举下，弱口令使整库加密形同虚设。建议长口令/密码短语；备份口令同理。
3. **NTP 信任未认证**：NTP 应答无密码学认证，网络攻击者可伪造偏移记录。TIME_SYNC 让「时间被改」可检出，但不构成可信时间戳——RFC3161 (TSA) 在 P1.5+。
4. **导出即脱离保护**：备份文件一旦离开 backups/（AirDrop、网盘、U 盘），其安全等同于一根口令保护的绳子；导出的引用材料同理。
5. **备份纪律靠使用者**：应用不强制备份节奏。3-2-1（三份副本、两种介质、一份异地）是使用纪律，不是系统能力。
6. **暂存窗口**：文件在 inbox/ 中等待扫描、在 quarantine/ 中滞留期间为明文；已隔离文件会一直保留直至人工处理。
7. **vault.db-wal / -shm**：WAL 伴生文件与主库同强度加密（SQLCipher 覆盖），但被外部工具随意拷走整目录时仍受口令保护——此条为提示而非缺口。
8. **单人开发供应链面**：依赖审计的深度受限于维护者精力；关键路径（加密、哈希）刻意选用久经维护的原语（SQLCipher、Node crypto、SHA-256）而非自研。

## 6. 测试边界（给安全研究人员）

- 只对你拥有的系统或合成数据做测试；
- 报告中绝不包含真实受访者数据——描述，而非持有；
- 最高价值的问题：受访者数据泄露、同意绕过、清除失效、证据篡改、确认绕过、未经授权的上传（详见 [SECURITY](../../SECURITY.md)「最高优先级」）。
