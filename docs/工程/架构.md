## 1. 系统概览

OpenField P1 = 桌面全功能端（Electron）+ 手机轻薄端（Expo，未实现）。桌面端是证据链的权威所在：真名映射、加密资料库、原始件封存全部只存在于桌面 vault。

```
┌────────────────────────────────────────────────────────────┐
│ iCloud / 相册 / 文件 App（系统搬运，只经手密文与原始件）        │
└───────────────┬────────────────────────────────────────────┘
                │ 文件自然回流 / 手机 bundle（Plan 3）
┌───────────────▼────────────────────────────────────────────┐
│ OpenField Desktop（Electron 44）                            │
│                                                            │
│  Renderer（sandbox，无 Node 权限）                           │
│    最小操作面板 ←→ window.openfield（contextBridge 白名单）   │
│                        │ IpcResult 信封                     │
│  Main 进程                                                  │
│    ipc.ts（zod 入参校验）→ services/*（框架无关 TS 模块）      │
│    watcher.ts（chokidar 监听 inbox/ → scanOnce）             │
│                        │                                    │
│  存储                                                       │
│    vault.db（SQLCipher 整库加密）+ originals/（只读封存）      │
└────────────────────────────────────────────────────────────┘
                │ 仅有的对外网络：NTP 校时（ntp.aliyun.com）
                ▼ 出站 UDP，无遥测、无上传
```

安全基线：`sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`；preload 对 IPC 通道做白名单过滤；所有 handler 入参经 zod 校验，返回统一 `IpcResult` 信封（`{ ok: true, data } | { ok: false, error }`）。窗口 1080×780（最小 860×600）；`setWindowOpenHandler` 拒绝应用内开窗，仅 `https://` 外链交系统浏览器打开。字体经 @fontsource 本地打包（Space Grotesk / Inter / JetBrains Mono），无 CDN 请求——与离线优先一致。

## 3. 数据与存储

### 3.1 数据目录

```
<home>/                          # 默认 Electron userData；--openfield-home=<path> 可指定
├─ vault.db                      # SQLCipher 整库加密资料库
├─ vault.db-wal / -shm           # WAL 模式伴生文件
├─ originals/<artifactId>/v1.<ext>   # 原始件只读封存，永不覆盖
├─ inbox/                        # 导入暂存（监听目录，可指向 iCloud 同步目录）
├─ quarantine/                   # 畸形 bundle 隔离区（8 位随机前缀防同名覆盖）
└─ backups/backup-<ISO 时间>.ofbackup # OFBK1 加密备份输出
```

`deviceId` 取主机名（`os.hostname()`），作为采集物 `device_id` 与部分链上 `actor`。

### 3.2 vault.db schema（migration v1 + v2）

| 表 | 说明 | 关键约束 |
| --- | --- | --- |
| `field_events` | 田野事件 | `id` PK |
| `encounters` | 访谈 | `event_id` FK → field_events |
| `artifacts` | 采集物登记 + `original_path` | `sha256` UNIQUE；`ref_id` UNIQUE 索引 |
| `participants` | 受访者档案（仅化名） | `pseudonym` PK |
| `participant_identity` | **真名映射（唯一允许真名之处）** | `pseudonym` PK FK → participants |
| `consent_records` | 知情同意（模板类型/签名或口头同意 Artifact/范围/撤回） | `encounter_id` FK |
| `memos` | 备忘录（反身性/分析/每日/速记 + 确认时间） | `id` PK |
| `inbox_items` | 导入暂存（状态机：pending/ingested/quarantined/rejected） | `id` PK |
| `time_sync_records` | NTP 校验记录 | `id` PK |
| `evidence_log` | **证据链（append-only）** | `seq` PK；两个 BEFORE 触发器拒绝 UPDATE/DELETE |
| `ref_sequences` | **RefId 序号水位（单调递增、永不复用；purge 不回收）** | `date_city` PK |
| `schema_migrations` | 迁移版本 | `version` PK |

隐私边界在三层同时强制：core 的 `Participant` 是 strictObject（类型层面拒绝 `real_name` 字段）；`repos.ts` 中只有 `setRealName` / `getRealName` 两个函数允许接触 `participant_identity` 表；分析层查询与 UI 默认不 JOIN 该表。

### 3.3 加密参数

- better-sqlite3-multiple-ciphers（SQLCipher v4 兼容模式）：`cipher='sqlcipher'`、`legacy=4` 必须在 `key` 之前、首次真实读取之前生效；
- 口令 ≥ 8 字符，**丢失无找回**（错误口令在首次读取时以 `SQLITE_NOTADB` 暴露，报「口令错误或文件已损坏」）；
- `journal_mode = WAL`、`foreign_keys = ON`。

## 4. 证据链协议

### 4.1 条目与哈希

```
EvidenceEntry { seq, ts, actor, action, payloadHash, prevHash, entryHash }

entry_hash = SHA-256(seq | prev_hash | ts | actor | action | payload_hash)
             （'|' 连接；无歧义前提：payloadHash 为 64 位小写 hex、action 为受控枚举、
              actor 不含 '|'、'\r'、'\n'——由 ChainSafeString 在 schema 层强制）
首条：prev_hash = 64 个 '0'（GENESIS_PREV_HASH），seq = 0
```

### 4.2 动作目录（10 个）

| action | 触发位置 | actor |
| --- | --- | --- |
| `INGEST_ARTIFACT` | ingest.ts：采集物入库 | `desktop` |
| `CREATE_EVENT` | registry.ts / inbox.ts（bundle 应用） | `desktop` / `bundle:<id>` |
| `CREATE_ENCOUNTER` | registry.ts / inbox.ts | 同上 |
| `CREATE_PARTICIPANT` | inbox.ts（bundle 应用） | `bundle:<id>` |
| `CONSENT_RECORDED` | ipc.ts（consents:record）/ inbox.ts（bundle 应用） | `desktop` / `bundle:<id>` |
| `CONSENT_WITHDRAW` | registry.ts：同意撤回（撤回后的完整记录为载荷） | `desktop` |
| `CREATE_MEMO` | registry.ts（每日日志）/ inbox.ts | `desktop` / `bundle:<id>` |
| `MEMO_CONFIRM` | registry.ts：草稿经人工确认 | `desktop` |
| `EXPORT` | export.ts：RefId 签发 | deviceId |
| `TIME_SYNC` | evidence.ts：NTP 校时 | `desktop` |
| `PURGE_SUBJECT` | purge.ts：PIPL 清除 | deviceId |

`payloadHash` 为该操作涉及内容的规范化 JSON 哈希（`computePayloadHash`：递归按键排序、丢弃 undefined、数组序保留——同结构对象产出唯一字节串）。`PURGE_SUBJECT` 的载荷只含删除**范围**（各实体计数），不含已删内容。

### 4.3 完整性不变式

1. **append-only 双重强制**：应用层无任何 UPDATE/DELETE 路径；库层 BEFORE 触发器直接 `RAISE(ABORT)`；
2. **链与业务同事务**：`appendEntry` 必须在调用方事务内执行——链条目与业务写库要么同时生效、要么同时回滚；
3. **篡改可检出**：任何历史条目被改动都会导致其后所有 `entry_hash` 校验失败；`verifyChain` 重放全链，报告首个断裂点（`brokenAt` + 原因）。

## 5. 原始件封存（Ingest）

`ingestFile` 单事务完成（失败时补偿删除已封存目录，不留孤儿）：

1. 拒收规则：空文件（0 字节，疑似 iCloud 未下载占位）、无法识别的扩展名（**拒绝猜测证据类型**）；
2. `sha256File` 计算源文件哈希 → 查 `artifacts.sha256` UNIQUE：命中即返回 `duplicate`，**绝不二次登记**；
3. 封存：copy 至 `<originals>/<artifactId>/.tmp-<uuid>` → **封存后二次哈希校验**（过程中文件变化即拒绝）→ rename 为 `v1.<ext>`（原子）→ `chmod 0444` 只读；
4. 登记：INSERT artifacts + appendEntry（`INGEST_ARTIFACT`，payloadHash = 文件 sha256），同一事务。

一切「编辑」产生 `v2`、`v3` 新文件，`v1` 永不改动。`transcript` 类型已建模（ArtifactType 枚举），外部转写文本导入属后续任务（目前 EXT_MAP 无对应扩展名）。

支持类型：`wav/mp3/m4a/aac` → audio；`jpg/jpeg/png/heic` → photo；`pdf/docx` → doc；`txt/md` → note。

## 6. 导入流（Inbox）

### 6.1 scanOnce 分类逻辑

对 `inbox/` 顶层每个文件（目录不存在视为空）：

| 情形 | 处理 |
| --- | --- |
| `.icloud` 占位符（`/^\..+\.icloud$/`） | 跳过计数，等本体回流 |
| 0 字节文件 | 跳过计数（macOS dataless 文件） |
| 同路径已有 pending 或 ingested 记录 | 跳过（重复投放去重） |
| `*.ofbundle.json` | decode → `applyBundle` 幂等应用；失败 → 移入隔离区并登记 `quarantined` |
| 其他文件 | 登记 `pending` InboxItem，按修改时间暗示归属当天的首个 FieldEvent |

单文件 `stat` 失败跳过不中断整轮扫描；隔离移动再失败则告警跳过——扫描永不因单个文件崩溃。

### 6.2 bundle 应用（手机端交接协议）

`applyBundle`（actor = `bundle:<id>`，ts = `bundle.createdAt`）单事务内：events/participants/encounters/consents/memos 逐条 `IfAbsent` 幂等插入、每条新插入入链；mediaRefs 生成 `pending` InboxItem（sourcePath = `bundle:<id>:<filename>`，带 sha256 与建议访谈），按现存 sourcePath 集合去重——重复应用同一 bundle 不产生重复待办。

BundleV1 为 strictObject：`schemaVersion` 恒为 1；`id` 链安全且 ≤ 121 字符（上界 = 128 − len('bundle:')，保证派生 actor 恒过 Actor 校验）。schema 校验失败的 bundle 进隔离区，不污染主库。P1 bundle 不做密码学签名：完整性由 ingest 时哈希登记建立。

### 6.3 watcher

chokidar 监听 `inbox/`（depth 0，`awaitWriteFinish` 150ms 稳定阈值），事件防抖 300ms 后触发 `scanOnce`；**未解锁时不扫描**；文件事件集中爆发时单次失败交给下次触发。启动时先确保目录存在（chokidar 对不存在目录永不生效）。

## 7. 引用与导出（Export）

### 7.1 引用 ID（RefId）

```
OF-YYYYMMDD-CCC-NNN[#Tmm:ss]
    │        │   │    └─ 录音内偏移：floor((capturedAt − encounter.startedAt)/1000)，clamp 到 [0, 5999]
    │        │   └────── 序号：`ref_sequences` 水位单调 +1（永不复用，PIPL 清除不回收；0-999）
    │        └────────── 城市码：3 位大写字母，继承自所属 FieldEvent
    └─────────────────── 日期：继承自所属 FieldEvent
```

签发规则（`makeCitation`）：采集物必须挂在访谈下（否则 `no-encounter` 拒绝）；**同意门禁**——audio 需未撤回的 recording 同意、photo 需未撤回的 portrait 同意，缺失则 `no-consent` 拒绝（doc/note/transcript 不受限）：采集与封存永不拦截（录音发生在系统之外，拦截只会伤及真实田野），但可被引用的材料必须存在相应且未撤回的同意——对研究者严谨（§2.1）、对受访者无感（§2.3）；**一经签发不可变更**——重复调用幂等返回既有 refId；序号在事务内从 `ref_sequences` 水位单调分配（`ref_id` UNIQUE 索引兜底数据完整性，正常路径不触发）。论文中可引用到「某段录音的第 mm 分 ss 秒」，审稿人可凭 sha256 验证材料未被改动。

### 7.2 OFBK1 加密备份容器

```
偏移   字段
0-4    MAGIC 'OFBK1'（ASCII，5 字节）
5-20   salt（16 字节随机）
21-32  iv（12 字节随机）
33-48  GCM tag（16 字节）
49-    ciphertext = AES-256-GCM( zip( vault.db 加密副本 + originals/ 全部原始件 ) )
密钥   scrypt(passphrase, salt, 32 字节)（Node 默认参数：N=16384, r=8, p=1）
```

vault.db 副本经 `VACUUM INTO` 产出——沿用当前连接的口令与加密参数，副本本身即加密库；临时副本在 finally 中清除。备份写入 `backups/`，目标已存在即拒绝（不静默覆盖）。`readBackup` 提供解密还原（返回 zip 字节流），UI 还原流程属后续任务。

## 8. 删除与清除（Purge，PIPL 删除权）

`purgeSubject` 流程：

1. **确认令牌**：`confirmToken` 必须与 `pseudonym` 完全一致——防误清、显式确认（PRINCIPLES §3 confirm-before-acting）；
2. **范围解析**：encounters（按 participant_ref）→ consents → artifacts → 关联 memos，形成清除范围清单；
3. **先删文件**：恢复 0644 后 `rmSync` 封存目录（Windows 只读位阻止删除；POSIX 无害）。顺序的理由：若后续 DB 事务失败，结局是「隐私已消失、登记残留」——verify 会以 `original-missing` **可见地**报告；绝不出现「文件还在、DB 删一半」的反向泄漏；
4. **路径围栏**：待删目录必须位于 originalsRoot 之内（`relative()` 校验），阻断借 artifact id 的路径穿越；
5. **后删记录**：单事务删除 memos → artifacts → consents → encounters → `participant_identity` → `participants`；
6. **留痕**：`PURGE_SUBJECT` 入链——只记录删除事实与范围（计数），不含已删内容。「清除行为本身」进入审计链，而受访者的数据彻底消失。

| `mock:clear` | — | 清除演示业务行与封存文件，证据链日志保留 |
| `mock:status` | — | 演示数据当前足迹（事件/访谈/采集物计数） |

只读查询通道（`vault:status`、`archive:*`、`evidence:list`、`inbox:list`、`verify:run`、`mock:status`）不写证据链；其余写操作均入链或按 §8 留痕。渲染层推送通道：`inbox:changed`（main → renderer，携带 ScanSummary）。所有业务通道未解锁时抛「vault 未解锁」。渲染层对 id 类输入做前置非空校验（如 `citation:make` 空 artifactId 时给出可读提示，不把 zod 转储抛给用户）；长错误信息在 toast 中截断显示。

## 10. 完整性校验（Verify）

`verify:run` 产出 `VerifyReport`：

```
{ chainOk, chainBrokenAt, chainReason, issues[], artifactCount, checkedAt }
```

四类 issue：

| kind | 含义 |
| --- | --- |
| `hash-mismatch` | 原始件重算哈希 ≠ 登记值（被改动/损坏） |
| `original-missing` | 登记在册但文件缺失（含 purge 中途失败的可见残留） |
| `orphan-directory` | originals/ 下存在未登记目录 |
| `unreadable` | 文件或目录不可读（目录不可读时**孤儿检查未执行必须可见**，不得静默） |

原则：校验失败必须可见（fail loud），不静默降级。

## 11. 可信时间（P1 简化）

本地设备时间可被修改，P1 策略：每次联网校时（@hapi/sntp，默认 `ntp.aliyun.com`，超时 5s），将时钟偏移以 `TIME_SYNC` 入链——「采集时刻被改过」事后可检出。NTP 应答不做密码学认证（偏移本身可被网络攻击者伪造），RFC3161 可信时间戳权威（TSA）属 P1.5+。
