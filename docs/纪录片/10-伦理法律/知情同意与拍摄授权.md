# 知情同意与拍摄授权

> 同意不是一个瞬间，是一条有版本、有范围、能撤回的时间线——把它从「一句话」拆成「四件事」，本章其余问题才有可执行的解法。

（注：上一章已把伦理判断做成规则，本篇把同意也做成规则。产品侧的禁止隐蔽采集、哈希固化、可审计删除见 [../../../PRINCIPLES.md](../../../PRINCIPLES.md) §2.1/§2.4 与 [../../工程/使用手册.md](../../工程/使用手册.md)；现场怎么说、怎么聊出来，见 [信任与被摄者心理](../06-采访方法/信任与被摄者心理.md) 与 [../../田野方法/07-伦理.md](../../田野方法/07-伦理.md)。本篇管**规范与凭证**。）

---

## 1. 四件事：大多数人混为一谈

| 事项 | 回答的问题 | 发生时间 | 失效条件 |
|---|---|---|---|
| **知情同意**（informed consent） | 你拍不拍我 | 开机前 | 用途变更、被隐瞒、被迫 |
| **使用授权**（release / license） | 拍到的东西你拿去干什么 | 开机前后谈妥 | 超出约定用途（学术变商单、短片变投流） |
| **发布确认**（publication confirmation） | 发布到哪个范围、哪个平台、哪一版 | 粗剪后、发布前 | 范围扩大（B 站变全网、比赛片变广告素材） |
| **撤回机制**（withdrawal） | 我反悔了怎么办 | 全程有效 | 无——撤回只能被兑现，不能被作废 |

四件事**分开谈、分开记**。最常见事故是：把第一件当成全部——对方说「你拍吧」，你记成他默许了后三件。台账里这也是四个独立字段（§7）。

## 2. 口头够用还是书面：一个乘法判据

【操作性建议】判据 = **可识别度 × 敏感度 × 传播范围**，三档各 1–3 分，乘积定档：

| 分项 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|
| 可识别度 | 背影/远景/不露脸 | 侧脸、声音可辨 | 正脸 + 姓名 + 地点职务 |
| 敏感度 | 工序、天气、菜价 | 工资、劳资纠纷、经营流水 | 疾病、债务、身份、家庭冲突、违法边缘 |
| 传播范围 | 素材库存档 | 单平台个人账号 | 比赛、发行、商用、多平台分发 |

| 乘积 | 形态 | 最低要求 |
|---|---|---|
| ≤4 | 街采快问快答、远景路过 | 口头同意 + 当场说清发哪个平台，记入台账 |
| 5–12 | 常规跟拍、摊贩店主访谈 | 口头同意必须**录音留痕**，发布前文字确认（微信明确回复也算） |
| ≥13 或任一专项 3 分的敏感类 | 可识别 + 高敏感 | 书面签署（模板见 [授权文书模板](../15-工具与模板/授权文书模板.md)），且核对理解程度（§4） |

注意两个不满足公式也必须升级书面的情形：出现**未成年人**（直接走 [弱势群体与儿童](./弱势群体与儿童.md)）；对方**明天还要为你的素材承担风险**（被拍地纠纷中、公司内部批评对象）。

## 3. 同意书要写哪几项才真的有效

一张只写「本人同意拍摄并放弃肖像权」的纸没有意义——放弃式条款既看不清你取得了什么，也保护不了任何一方。有效同意书的最小集【操作性建议】：

| 项 | 写什么 | 不写的后果 |
|---|---|---|
| 用途 | 具体到发布渠道与性质：个人账号纪实栏目 / 参赛 / 未来发行，商用与否 | 用途变更即无权（[../../PRINCIPLES.md](../../../PRINCIPLES.md) §2.4 要求重新同意） |
| 语言与理解确认 | 用对方的语言（方言区就写方言能讲明白的话）；留一行「已向本人逐条解释」并让对方复述要点 | 「签了但没懂」= 未同意（§4） |
| 期限与范围 | 授权几年、发到哪些平台、能否剪辑再加工 | 无限期授权吓退人，也让自己背雷 |
| 可撤回 | 撤回联系方式、撤回后你做什么（下架/重制/匿名化） | 不可撤回的同意书在伦理上无效 |
| 匿名化选项 | 化名、遮脸、变声、只出声音，任选组合（§6） | 对方只能整段同意或整段拒绝，你失去素材 |
| 收益或致谢约定 | 无报酬就写明无报酬；有报酬写清金额与性质；长期项目可写片尾致谢 | 「说好的呢」是纠纷源头，白纸黑字对双方都好 |

签字一式两份或拍照回传；签署人像普通素材一样入库固化（现场直拍签署照片进 `01_ORIGINALS/STILL/`，做法见 [现场工作流与安全](../07-拍摄执行/现场工作流与安全.md)）。

## 4. 签了字不等于取得同意：三种假同意

| 失效类型 | 现场识别信号 | 处置 |
|---|---|---|
| 理解不足 | 签字快、不问任何问题；你解释时他点头，但复述不出来 | 现场补解释，让对方用自己的话复述一遍用途；复述不出→按未同意处理 |
| 权力污染 | **老板在场时员工签的字无效**；房东在场时租客、车间主任在场时工人，同理 | 换场合单独确认；确认不了就放弃这个人的素材或只用匿名化形态 |
| 时机倒置 | 上来就掏纸笔；或聊到最激动处喊停去拿同意书 | 先聊天后签字（§5 流程）；情绪高点不办手续 |

【通行共识】同意的构成要件是**充分知情 + 自愿 + 明确**（PIPL 第 14 条的表述与此一致，条文以现行有效文本为准，逐条核验见 [../../田野方法/07-伦理.md](../../田野方法/07-伦理.md) §3.1）。三者缺一，纸质凭证只是你的心理安慰。

## 5. 拍摄前 60 秒说明脚本

用你自己的口吻，不要官话。骨架五句【操作性建议】：

> 「师傅，我是拍纪录片的，一个人，就叫曹亚仑，B 站号是 ××，你可以现在搜一下我平时拍的东西。」（我是谁、给谁看）
> 「我想拍你干活/卖货的样子，再加一段咱俩聊天，最后发在这些平台上，也不赚钱，就是攒长期作品。」（拍什么、发哪儿、有无报酬）
> 「要是哪句你不想让我用，随时说一声，我就停；回头你说删，我就删，删干净为止。」（当场可停 + 事后可撤）
> 「不想露脸、想换个名字都行，你说怎么弄我就怎么弄。」（匿名化是选项不是对抗）
> 「你要是同意，我把这几条写在一张纸上你过目；不点头我就不开机。」（凭证在后，不在前）

三句禁忌：**不许**在对方求助、诉苦、情绪崩溃的当口掏出同意书；**不许**把「发网上」省略成「留个纪念」；**不许**在老板、工头、房东视线内让他的下属签字（§4 权力污染）。

## 6. 分层同意：把二元题变成五档菜单

「同意/不同意」是最差的设计，因为它逼对方在「全给」和「全不给」里选。给对方一张菜单【操作性建议】：

| 档位 | 内容 | 台账记录 | 典型对象 |
|---|---|---|---|
| A 全名出镜 | 正脸 + 真名 + 职务 | 签署/录音双留痕 | 习惯镜头的店主、自媒体人 |
| B 化名出镜 | 正脸，姓名与厂名用化名 | 说明化名规则（字幕处理见 [字幕与无障碍](../08-剪辑后期/字幕与无障碍.md)） | 在职员工、纠纷当事人 |
| C 只出声音 | 画外音/同期声，配空镜 | 声音也算可识别信息（口音+职务可定位） | 怕出镜但愿说话的工人 |
| D 画面可用不说话 | 背影、手部、远景剪影 | 记「无语句」；背景里若有单据文字要遮 | 只想被记录 process 的人 |
| E 不参与本次 | 拒绝 | 记 DECLINED，素材保留永不进导出 | 任何时候 |

档位可升不可默降：拍的时候按 B 谈，剪出来不能按 A 用。**E 是合法选项**，被记 DECLINED 的素材没有「以后悄悄用」的余地。

## 7. 与产品机制对接 + 同意台账

OpenField 侧（操作路径以 [../../工程/使用手册.md](../../工程/使用手册.md) 为准）：知情同意在采集登记面板按「录音 / 肖像 / 发表」三类分别留痕，每份同意单独入证据链（`CONSENT_RECORDED`）；撤回在档案库操作，撤回后引用门禁即刻生效；当事人行使删除权走危险区 PIPL 删除流程，全链路可审计清除（[../../../PRINCIPLES.md](../../../PRINCIPLES.md) §2.4）。**要点：同意有版本**——用途、范围、档位每次变更都记新版本，旧版本不覆盖。

**同意台账**（项目 `05_DOC/同意台账.md`，一行一档，与素材日志的授权五值枚举共用一个主键）【操作性建议】：

| 字段 | 示例 | 说明 |
|---|---|---|
| 人物化名编号 | `P07-老周` | 真名不进剪辑侧 |
| 事项 × 四事 | 同意=录音+肖像；授权=个人账号；发布=v02 前确认；撤回=未行使 | 每事独立状态 |
| 时点与形式 | 2026-09-12，口头+录音留痕 / 书面签署照 | 形式对应 §2 的档位要求 |
| 范围摘要 | 全名或化名档位（A–E） | 默降=违规 |
| 变更历史 | 2026-10-03 升级为书面；2026-11-11 撤回发表授权 | 只可追加，不可抹行 |
| 凭证路径 | 同意书扫描件文件名 / `OF-` 引用编号 | 与 `01_ORIGINALS/STILL/` 对应 |

与 [素材管理与日志](../08-剪辑后期/素材管理与日志.md) §6 的硬规则打通：台账里没有有效同意记录（或状态为 `NOTASKED/DECLINED/REVOKED`）的素材，剪辑侧一律进 `X_不可发布` 染色分组，导出扫描时被硬排除——**授权状态是快照，每次开剪前从台账重新拉一次**。

## 8. 发布确认的执行细节

四件事里最容易省、后果最重的是第三件。【操作性建议】：

- **确认对象是「这一版发这个渠道」**，不是「这部片子」。v01 上 B 站的确认不覆盖 v02 上抖音，更不覆盖将来投稿参赛；每次范围扩大，新增一版确认记录（变更历史列）。
- **确认要能看到内容**：给对方看的最低配置是「有你出场的段落 + 你说的话的字幕」，不必等全片精剪；用 §5 的时间码清单法组织回看，别让对方在三十分钟素材里自己找你剪过的三十秒。
- **文字确认的话术把「不」写进去**：「你看完这三段，哪里不想用直接说，我改；不回消息我按不同意处理，不定档发布。」默认沉默=不同意，这条规则本身也要事先告知。
- **长期跟拍的确认节奏**：每次公开发布前确认一次，而不是项目开始时签一张「以后都同意」的总约——总约在伦理上属于 §4 的理解不足型假同意高发区（签的人无法预演一年后的成片）。
- **留痕的层级**：书面签署 > 录音/录像确认 > 可截图的文字回复 > 无留痕口头。台账记到哪个层级，§2 判据要求哪个层级，不达标就补；补不到按最保守档位使用或不使用。

## 常见误区

| 误区 | 为什么错 | 更正 |
|---|---|---|
| 「他说你拍吧=全授权」 | 四件事混成一件事（§1） | 逐项谈、逐项记 |
| 「打了招呼就是同意」 | 招呼回答不了用途、范围、撤回 | §3 六项至少口头讲全 |
| 「有签字就不管懂没懂」 | 理解不足即假同意（§4） | 让对方复述要点 |
| 「老板同意了员工自然就同意了」 | 权力污染；员工在管理链内无自由拒绝 | 换场合单独确认 |
| 「先拍爆再说，不用他同意」 | 「来不及」的拍法没有正当版本；禁隐蔽采集是宪法级 | 不开机，或改 D 档不涉人的空镜 |
| 「撤回太麻烦，拖一拖」 | PIPL 第 15 条要求撤回便捷可用（以现行文本为准，核验见 ../../田野方法/07-伦理.md） | 撤回即从工程与导出移除并记录所撤版本 |
| 「匿名化是我的恩赐」 | 匿名化是对方菜单上的正当选项（§6） | 谈同意时主动给 |
| 「口头同意没凭证=白聊」 | 口头+录音留痕也是凭证（§2 中档） | 补录音入链，别弃素材造假 |

## 实操要点

- [ ] 开机前跑 §2 乘法判据定档：低档口头 + 记台账，高档必须书面（模板见 [授权文书模板](../15-工具与模板/授权文书模板.md)）。
- [ ] §5 五句话脚本背熟；掏同意书的动作永远放在聊天之后。
- [ ] 老板、工头、房东在场时，其下属/租客/工人的签字一律重谈。
- [ ] 同意按 A–E 五档给菜单，记入台账档位字段；档位可升不可默降。
- [ ] 台账与素材日志同一主键，`NOTASKED/DECLINED/REVOKED` 状态在导出扫描中硬排除。
- [ ] 用途或范围每变更一次，新增一版同意记录；开剪前重新拉一次授权状态。
- [ ] 撤回发生时：停使用→移除导出→通知已发布平台→台账追加变更行，四步不跳。
- [ ] 每周五整理时核一遍：本周新增素材有没有台账空行（做法见 [素材管理与日志](../08-剪辑后期/素材管理与日志.md) §10）。
