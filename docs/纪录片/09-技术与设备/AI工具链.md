# AI 工具链

> 这一篇的目的不是让你多用工具，而是让你在一台疲惫的机器前，不会把「看起来对」当成「是对」。

**核心纪律只有一句：所有 AI 输出都是等待你确认的提案。** 出处见 [PRINCIPLES](../../../PRINCIPLES.md) §1「AI 是同事，不是先知」与 §5「未经确认即执行敏感操作 = P0 级缺陷」。本篇不推荐任何具体厂商、模型或版本；只给**可落地的流程、判据与三条禁令**。

---

## 一、选型第一判据：能不能导出可审计的中间产物

| 判据 | 通过 | 不通过 |
|---|---|---|
| 中间产物可导出 | 时间码 + 文本 + 置信度/差异，存成开放格式文件 | 只能在其界面里看，导出只有成品 |
| 修改可追溯 | 输出与原素材片段时间码可回连 | 输出后无法定位它来自哪一段 |
| 可回滚 | 结果是叠加层（标记、字幕文件、日志草稿） | 直接改写素材命名、时间线或原始记录 |
| 数据去向可说明 | 明确本地处理，或云端可说明保留政策 | 条款说不清；默认上传 |
| 断网可用 | 核心功能离线可跑（PRINCIPLES §2.2 离线优先） | 断网即整条流程停摆 |
| 输出格式开放 | 文本、表格、标准字幕、带时间码的结构化数据 | 私有工程锁定 |

**一句话规则**：不能导出可审计中间产物的工具，不进入流程。理由不是洁癖，而是——**你无法把一次无法解释的输出写进事实核查记录**（[事实核查与更正](../10-伦理法律/事实核查与更正.md)）。

## 二、可以落地的八个介入点

### 2.1 转写

| 环节 | 做法 | 不可省的部分 |
|---|---|---|
| 机器转写 | 长素材分段跑；分段边界与时间码对齐 | 方言、行话、人名、地名、厂名、工序名**必错**（见 [字幕与无障碍](../08-剪辑后期/字幕与无障碍.md)） |
| 人工校对 | **以音频为准**，不以机器文本为准；听不清就回原声，不要顺读猜 | 机器写顺了的句子最容易骗人 |
| 差异登记 | 保留机器稿与人工稿两份，标出改动处 | 改动处往往是事实关键点 |
| 命名与定位 | 每段落带素材 ID 与时间码，与日志字段共用（[素材管理与日志](../08-剪辑后期/素材管理与日志.md)） | 无时间码的转写稿不能作为引用依据 |

**边界**：转写稿不是记录，是**待核对的索引**。任何进入成片、旁白、字幕、报道文字的引语，必须回到音频或当事人本人复核。

### 2.2 素材日志与检索摘要

AI 可以读一遍转写与画面描述，写出一份日志**草稿**：时间码、人物、动作、场景、可讨论关键词、疑点。你做的是核对与改写，不是接受。

| 允许 | 禁止 |
|---|---|
| 生成候选标签与关键词 | 直接以 AI 摘要当作素材内容的事实陈述 |
| 按「谁在做什么」粗排段落 | 让 AI 判断「这句话是否真实」 |
| 提示矛盾之处供你复查 | 用摘要替代自己看完关键场（判断力来自看完） |
| 汇总当日素材量与耗时 | 把敏感人物身份写进会上传云端的提示词 |

**检索的诚实提醒**：摘要检索召回的是「模型认为相关」，不是「现场相关」。漏掉的那部分不会报错——这是这类工具最危险的失效方式：**沉默的漏**。

### 2.3 粗剪建议与时间线检索

| 用途 | 现实收益 | 代价 |
|---|---|---|
| 按关键词/时间码拉候选片段列表 | 省找片时间，最扎实的一项 | 需要日志质量先过关 |
| 按台词或场景相似度推荐串联 | 提供第二种看结构的机会 | 会强化「说得顺」优于「说得真」的偏好 |
| 自动踩点、自动配乐、自动转场 | 基本不要 | 纪录片节奏判断不可外包，见 [蒙太奇与长镜头](../03-电影语言/蒙太奇与长镜头.md) |

纪律：AI 给的顺序**永远不直接成为成片顺序**。它进的是「备选清单」，不进时间线。

### 2.4 字幕：生成 → 校对 → 双语

标准流程固定为四步，任何一步跳过都会把机器错误固化成公开文字：

1. 机器生成时间轴草稿（阈值与规格见 [字幕与无障碍](../08-剪辑后期/字幕与无障碍.md)）。
2. 逐句听音校对，专有名词按词表统一。
3. 校对后仍需**人工通读一遍全篇**，检查断句与语义切分是否改了意思。
4. 双语版本对齐后入交付附包，翻译债登记。

### 2.5 翻译

P1 中文先行；英文不是修饰，是双语对等义务（PRINCIPLES §4：双语不对等 = 未完成，每笔翻译债记录在案）。

| 风险 | 表现 | 处置 |
|---|---|---|
| 语域被抹平 | 车间口语被译成书面语，人变成「案例」 | 保留原始说法，译文旁注明 |
| 术语误置 | 工序名、岗位名被意译 | 术语表固定，不意译 |
| 沉默被翻译 | 停顿、咳嗽、方言拒绝被省略 | 非语言信息一并处理，必要时加注 |
| 债未登记 | 只有中文精修、英文是机翻 | 写进双语债记录，进交付附包（[交付母版与规格](../08-剪辑后期/交付母版与规格.md)） |

### 2.6 归档元数据补全

AI 可批量补写：地点、时间、人物角色、授权状态建议、素材分级候选（L1/L2/L3 定义见 [素材管理与日志](../08-剪辑后期/素材管理与日志.md)）。

**唯一例外：授权状态不允许 AI 填。** 五值授权枚举（GRANTED / VERBAL / NOTASKED / DECLINED / REVOKED）只能来自你自己的现场记录，因为它是一个**事实断言**，不是一个可以推断的标签。

### 2.7 打码与化名处理

| 任务 | AI 能做到 | 必须人做的 |
|---|---|---|
| 人脸识别与批量打码 | 大幅省时 | 逐帧抽检：侧脸、遮挡、小孩、反光面、镜中倒影 |
| 车牌/工牌/单据文字遮盖 | 高召回 | 判断哪些信息真的敏感（工序 + 岗位 + 时间 = 可定位到人） |
| 化名映射表生成 | 生成候选 | **映射表本地加密保管，永不与成片同地存放**（[证据链与可复核性](../../工程/架构.md)） |
| 音频变声 | 提供选项 | 变声效果与可识别风险的判断要听完整版 |

打码不是「遮了就行」，遮不住会**制造虚假的安全感**；承诺遮脸与化名的口径见 [长期跟拍](../07-拍摄执行/长期跟拍.md)：不保证绝对不可识别。

### 2.8 介入点登记表

每个 AI 介入点占一行，与处理登记同生命周期。这张表是你在两年后回答「这句话是谁说的」的唯一凭据。

| 字段 | 内容 | 为什么必须有 |
|---|---|---|
| 素材 ID 与时间码 | 对应到哪一段 | 无定位即不可复核 |
| 介入类型 | 转写 / 摘要 / 翻译 / 打码 / 检索 | 风险等级不同 |
| 处理路径 | 本地或云端；云端要能说明保留政策 | 禁令一的执行证据 |
| 输出存放 | 文件名与位置 | 保持可回滚 |
| 核对方式 | 听原声 / 问本人 / 查记录 / 逐帧抽检 | 「我看过」不算方式 |
| 核对人与时间 | 本人，日期 | 有他人参与时区分责任 |
| 遗留问题 | 听不清、方言存疑、遮不住的位置 | 不许清空，只许追加 |

**这条表同时是自我约束**：填不出「核对方式」的那一行，就是还没有核对完的一行。

## 三、三条禁令（无例外）

| 禁令 | 内容 | 依据 |
|---|---|---|
| **一：不上传无法说明数据保留政策的素材** | 任何当事人的音视频、可识别身份的转写、未公开的受访者信息，不得交给**不能明确说明数据保留政策**的第三方服务。PIPL 与 PRINCIPLES §2.4 的共同要求 | 见 [中国法律边界](../10-伦理法律/中国法律边界.md)、[伦理总论](../10-伦理法律/伦理总论.md) |
| **二：不用生成模型补、造、换现场** | 不得重绘、伪造或替换任何在场画面与声音，**包括「补一段环境音」「让他说得顺一点」「把噪点里的人脸生成清楚」** | 影像证据性见 [不可重复事件现场](../07-拍摄执行/不可重复事件现场.md) |
| **三：影响事实断言的 AI 产出必须披露** | 凡进入成片的 AI 辅助内容（转写、翻译、摘要、打码、任何合成），在交付附包的**处理登记**中逐项登记，格式与 08 章一致 | 见 [交付母版与规格](../08-剪辑后期/交付母版与规格.md)、[事实核查与更正](../10-伦理法律/事实核查与更正.md) |

第二禁令的判断线很清晰：**观众以为那是当时在场的声音或画面吗？** 是，就不许做。不做任何规避平台检测、规避权利人、绕过审核的技术建议。

## 四、本地模型 vs 云端服务

| 维度 | 本地 | 云端 |
|---|---|---|
| 质量 | 长文本与方言理解通常弱一档 | 通常更强，但会「更流畅地错」 |
| 隐私 | 素材不出机器，禁令一风险最低 | 取决于条款；默认按「会被人看到」处理 |
| 断网可用 | 可用（符合离线优先） | 不可用 |
| 算力与电量 | 笔记本长时间推理发热、掉电快 | 轻，但依赖上行 |
| 上手时间 | 安装、模型选择、环境折腾计入工时 | 快，五分钟能跑第一份 |
| 失败模式 | 慢、跑不完、质量不稳 | 政策变化、接口变动、计费、静默改行为 |
| 可审计性 | 输出与版本可锁在你自己手里 | 版本、参数、提示词由平台单方变化 |
| 适合做什么 | 含可识别身份的素材、转写、打码 | 公开资料的检索式整理、无身份信息的语言润色草稿 |

**按任务分线，不按偏好站队**：涉及当事人身份与未授权内容的一律本地；只有已公开、去身份、无原始媒体上传的路径才考虑云端。**用眼负荷也是成本**：本地跑失败的反复重试、云端网页界面的长文本核对，都会吃掉 07 章的屏幕时长预算。

## 五、把「确认」做成机制，不是心情

PRINCIPLES §3 的要求是可复用模式：**预览 → 显式确认 → 可回滚 → 留痕**。落到工具上：

| 步骤 | 具体动作 |
|---|---|
| 预览 | AI 输出先进「候选」区，不进正式文件 |
| 显式确认 | 你手动改状态为「已核对」，并写下核对方式（听原声 / 问本人 / 查记录） |
| 可回滚 | 原稿不覆盖；新版本新文件名，与原始文件永不覆盖的原则一致 |
| 留痕 | 谁改的、改了哪几处、依据什么，写进日志与处理登记 |

**疲劳时段禁止做确认动作。** 与 07 章疲劳表同期：晚上十点之后不做转写确认、不做打码验收、不发布任何文字。理由很直接：这类工作的失败不是慢，是**错得很像对的**。

## 常见误区

| 误区 | 代价 | 更正 |
|---|---|---|
| 把 AI 当剪辑师 | 结构与节奏变成模型的偏好，作者判断退化 | 它只进备选清单，不进时间线 |
| 把转写当记录 | 方言与行话的错误被写进字幕、旁白、事实陈述 | 转写是索引；引语回原声 |
| 用生成补素材 | 影像证据性归零，且无法披露得起 | 禁令二 |
| 让 AI 判断真伪 | 它优化的是「像真的」，不是「是真的」 | 事实核查路径见 10 章 |
| 摘要代替看完素材 | 关键场漏看，且**漏不会报错** | 关键场必须亲眼看 |
| 相信置信度数字 | 校准不透明，高置信错误常见 | 只当排序线索，不当验收 |
| 直接上传素材图方便 | 违反 PIPL 与 PRINCIPLES §2.4，且不可撤回 | 禁令一 |
| 授权状态让 AI 填 | 把事实断言变成推断 | 只来自现场记录 |
| 打码全自动收工 | 镜中倒影、侧脸、单据文字漏出 | 逐帧抽检 + 判断敏感性 |
| 只留机器稿 | 无法说明改动来自谁 | 机器稿与人工稿并存 |
| 不做披露登记 | 成片可信度经不起一次追问 | 逐项写入处理登记 |
| 疲劳时做确认 | 高负荷下把错认成对 | 疲劳时段禁止确认动作 |

## 实操要点

- [ ] 每个 AI 工具先过第一节六条判据；不能导出可审计中间产物的，直接从清单划掉。
- [ ] 在流程里写死一句：**任何 AI 输出默认状态是「待核对」**，只有你手动改状态才算数。
- [ ] 三条禁令抄成卡片贴在机器旁；每次引入新工具先对照一遍。
- [ ] 转写稿与人工稿两份并存，改动处保留；关键场必须回看原素材。
- [ ] 涉及身份的素材一律本地路径；云端使用前能说出数据保留政策。
- [ ] 授权状态、事实断言、成片顺序三项，永不交给 AI 决定。
- [ ] 所有 AI 辅助逐项写入交付附包的处理登记；翻译债同时登记。
- [ ] 每晚收工时问一句：今天有没有哪一步我把「看起来对」当成了「是对」？有，就记进当日事故记录（模板见 [现场工作流与安全](../07-拍摄执行/现场工作流与安全.md)）。
