# 编码存储与备份

> 素材是数据资产，不是「拍完就有的东西」。数据资产的判断标准只有一条：能不能在任意一天，由不是你本人的人，把它完整还原到可用状态。

交付侧的母版与分发编码、哈希清单五列表、公开仓库禁放原片的硬规则，唯一权威是 [交付母版与规格](../08-剪辑后期/交付母版与规格.md)；现场时间线（现场 +1、当晚 +2、离城前 ≥3 份）与格式化四条前提的唯一权威是 [现场工作流与安全](../07-拍摄执行/现场工作流与安全.md)。本篇管的是**它们上游的技术选择**：录什么格式、存在什么介质、怎么把备份变成可审计流程。

---

## 一、把素材当数据资产：三个判据

| 判据 | 问法 | 不合格的表现 |
|---|---|---|
| 可还原性 | 三年后换一台机器还能打开并剪吗 | 只有厂商专用容器能读；缺音轨映射信息 |
| 可验证性 | 怎么证明这份和原始那份一模一样 | 只看文件大小和日期 |
| 可归属性 | 这份素材对应哪一天、哪台机、哪张卡、谁同意拍的 | 目录叫「新建文件夹 3」；授权状态在脑子里 |

**唯一一条绝对禁区：卡满就地删除。** 就地删除删掉的不是文件，是一次不可重拍的在场。任何「先删一点腾地方」的念头都等价于把当天后半场押在运气上。卡满了的正确动作是换卡、或当晚倒完再按流程处理；格式化只能满足 07 章四条前提之后才做。

## 二、机内编码：先问可用性，再问画质

| 类别 | 特点 | 什么时候选它 |
|---|---|---|
| 长 GOP（H.264 / H.265 等帧间压缩） | 体积小；解码靠前后帧，坏一帧可能连坏一片；剪辑时 CPU 重 | 单机长期跟拍、容量与续航受限、当日就倒素材 |
| 全内帧（All-Intra）与高位深档位 | 每帧独立，容错与剪辑响应好；体积成倍上升 | 大量运动、需要二次调色、机器扛得住 |
| 中间级/编辑优化格式 | 剪辑最顺，体积最大 | 只在**存储与拷贝预算明确**的项目上用；否则备份时间会吃掉拍摄时间 |
| 机内无损/RAW 类 | 后期空间最大，链路最长（需解码、需元数据配套） | 一人项目通常不划算：省下的时间在整理上 |

选择纪律：**格式跟着机器和存储走，不跟着论坛排名走。** 若主机只有长 GOP 档位，那就把预算花在存储和代理上，而不是换主机（换机型的迁移代价见 [摄影机与镜头选择](./摄影机与镜头选择.md)）。声音侧记录格式与位深口径见 04 章：分轨、不做有损内录。

## 三、代理剪辑：弱机器上的解放

代理（proxy）不是画质降级，是把「能不能剪」从机器能力里解耦出来。

| 项 | 建议 | 代价 |
|---|---|---|
| 代理分辨率 | 1080p 或更低即可满足剪判断；数字不由画质决定，由「你能不能在 30 分钟内看完一段素材」决定 | 精细遮罩与合焦判断需回切原片 |
| 代理编码 | 剪辑友好档位，接受大体积；或直接用低码长 GOP 换存储 | 前者占盘，后者吃 CPU |
| 回连（relink） | 原片与代理保持同一目录结构与命名，只加后缀区分 | 一旦有人手改文件名，回连断；命名规则见 [素材管理与日志](../08-剪辑后期/素材管理与日志.md) |
| 生成时机 | **倒素材当晚批量生成**，不在剪辑现场边剪边转 | 当晚多花一小时，换之后每周省若干小时 |
| 归档 | 代理可再生，**不属于必须保留的资产** | 别把代理当备份 |

**在低配机器上不搭代理流直接剪高位深素材，结果不是慢，是每天多两小时等待、少两小时判断。** 等待时间会直接压进你的健康预算（07 章屏幕时长与离屏节律）。

## 四、容器、音轨数与元数据

| 项 | 器材侧决策 | 为什么必须在开机前定 |
|---|---|---|
| 容器 | 选主流、工具链齐全、支持多音轨与时间码记录的容器；避免只有厂商自家软件能读的配置 | 后期换机器、换软件、写脚本处理都会撞墙 |
| 音轨数 | 按 [收音装备](./收音装备.md) 的通道表设定（主轨 + 安全轨 + 环境/备用） | 开机设 2 轨、现场实际需要 4 轨，第 3、4 轨永久丢失 |
| 采样率与位深 | 见 04 章，本篇不重复数值 | 相机与录音机两边不一致时，后期要重采样并登记 |
| 时间码/元数据 | 相机日期、时区、帧率、卷号写进文件而非笔记 | 三天后没人记得 D03 是哪天 |
| 文件系统 | 单文件超 4 GB → 需要支持大文件的文件系统；跨平台与只读归档的取舍要提前测 | exFAT 通用但更脆弱；专用格式换机器即读不了 |

## 五、分辨率与帧率：不混帧率

| 规则 | 具体做法 |
|---|---|
| 一个项目一个基准帧率 | 依交付端与主机能力定一次，写进项目首页；帧率基准以拍摄帧率为基准，不做转换式交付（见 08 章） |
| 可变帧率（VFR）素材单独标记 | 手机、屏幕录制、部分直播档常是 VFR |
| 慢动作需求 | 只有「确实需要放慢且不介意画质」时才用高帧率；高帧率素材进时间线要按 08 章口径处理 |
| 分辨率 | 按交付端上限录；不放大（08 章：分辨率不放大） |

**混帧率的具体后果（不是抽象麻烦）**：

1. 25p 与 50p 混在同一时间线：要么把 50p 抽成 25p（运动断续、出现步频感），要么整条时间线升 50p（25p 素材需补帧或出现 judder）。两种都要重做节奏判断。
2. 不同帧率素材的**音频漂移**：长镜头最明显——开头对齐、结尾差几十毫秒到几百毫秒，你会误以为是同步错误而去重打点，白耗时间。
3. 快门与帧率互相牵连：帧率一改，03 章的运动模糊下限与 05 节的频闪修正档位都要重算。
4. 字幕与逐字稿时间轴跨帧率转换时会出现尾段偏移，见 [字幕与无障碍](../08-剪辑后期/字幕与无障碍.md)。

**纪律**：一场之内不改帧率。要改，就登记为「新的基准日」，并在日志里写明。

## 六、介质可靠性现实

不要相信「新的就安全」。各类介质的失效方式完全不同。

| 介质 | 典型失效 | 可救性 | 适用 |
|---|---|---|---|
| SD 卡 | 控制器锁死成只读、突然掉容、文件系统损坏、触点氧化 | 低；锁死后常见但取数据要专业手段 | 拍摄介质，**绝不当日之后当存储** |
| CFexpress 一类高速卡 | 发热掉盘、掉文件、接口松动 | 低 | 高码流必需时 |
| 便携 SSD | 主控/供电失效即整盘不可读，往往是**全有或全无**；线比盘更容易坏 | 低 | 现场拷贝、剪辑工作盘 |
| 机械硬盘（HDD） | 磁头/电机机械故障；摔一下就够 | 相对高（盘片常可用专业手段读） | 冷备份、归档 |
| NAS / 双盘 | 卷损坏、误同步、被勒索/误删、电源事故 | 中 | **不是备份**，是方便的共享存储 |
| 磁带（LTO 一类） | 老化、驱动器代次断代 | 中 | 长期冷存，前提是你还能读到 |

**两条常被忽略的事实**：
- 固态硬盘**不适合断电长期封存**：电荷泄漏会随时间累积，存放数年不等于安全。长期保存要通上电、跑一次校验。【通行共识】
- 叠瓦式（SMR）机械盘在大容量顺序写入与重建时性能与可靠性都不利；做备份盘选明确非叠瓦的类别（以厂商标注为准）。【通行共识】

## 七、现场版 3-2-1：把它写成可审计的 SOP

07 章给的是时间线，本节给的是**执行动作与证据**。

| 份 | 位置 | 何时完成 | 证据 |
|---|---|---|---|
| 1 | 原始卡（不动） | 拍摄结束前不格式化 | 卡号与卷号记录 |
| 2 | 现场拷贝（当日倒出的工作盘） | 收工后 60 分钟内 | 台账第 1 行 |
| 3 | 住所/后方拷贝 | 当晚或次日，离城前 | 台账第 2 行 |
| +1 | 异地（云端或寄回后方硬盘） | 每周至少一次 | 台账第 3 行 + 云端策略确认 |

**校验纪律：比对哈希，不比对文件大小。** 字节数相同而内容不同是真实故障模式（截断、坏道尾部、拷贝工具静默失败）。

```
# 源与目标分别生成清单，再比对
shasum -a 256 *  > /path/manifest_src.sha256
shasum -a 256 *  > /path/manifest_dst.sha256
diff manifest_src.sha256 manifest_dst.sha256   # 无输出才算完成
```

或用具备复制后校验（copy-verify）能力的工具，让工具做这件事并把日志留下。**没有比对结果的拷贝不算完成**，这一步对应 PRINCIPLES §2.1 的证据链要求（仅可追加日志、原始文件永不覆盖，见 [PRINCIPLES](../../../PRINCIPLES.md)）。

## 八、还原演练：没演练过的备份等于不存在

用运维的话说：**没有做过 restore 的备份，状态是 unknown，不是 ok。** 只验哈希不够，哈希只能证明「字节一致」，不能证明「介质可读、软件能解、项目能回连」。

| 演练 | 频率 | 通过判据 |
|---|---|---|
| 从最远副本抽 3 段（最长、最大、含多轨音频）拷到新目录并完整播放至尾 | 每季度一次 | 播放无中断、音轨数与声道正确 |
| 用工程文件做一次**离线回连**测试（把原片改名到测试目录，再 relink） | 每季度一次 | 能在十分钟内全部回连 |
| 从台账任意一行做一次全量恢复演练（挑最小的一天） | 每半年一次 | 恢复出的清单哈希与台账一致 |
| 换机器/换软件版本后首次全链演练 | 每次变更后 | 工程打开、代理回连、字幕时间轴对齐 |
| 记录耗时 | 每次 | 耗时突然变长 = 介质或网络在退化 |

演练结果写进同一本台账，形成一条可追加的时间线。失败不清零、不删记录，只加一条修复说明。

## 九、备份台账字段

一行一份副本，字段固定，不改结构（与 [素材管理与日志](../08-剪辑后期/素材管理与日志.md) 的最小元数据八字段共用命名）：

| 字段 | 例 | 说明 |
|---|---|---|
| 拍摄日代号 | D07 | 与 07 章命名一致 |
| 卡号 / 卷号 | A03 | 原始介质唯一编号 |
| 源路径 | /CARD/A03/ | 只读，不改 |
| 副本位置 | 现场盘 1 / 住所盘 / 云端 | 一行一份 |
| 字节数与文件数 | — | 只做粗筛，不作完成判据 |
| 哈希清单文件 | D07_A03.sha256 | 存在哪、哪天上链 |
| 校验结果 | PASS / FAIL + 差异行数 | FAIL 不允许被后续记录覆盖 |
| 执行人与时间 | 本人 / 后方，UTC+8 | 有第三方参与时写清 |
| 格式化许可 | 满足 07 章四条前提 / 未满足 | 未满足即不得格式化 |
| 异常与处置 | 读卡器换用、重跑、耗时 | 事故也要留痕（07 章事故记录模板） |

## 十、云端边界：离线优先、端到端加密、默认关闭

| 情形 | 结论 |
|---|---|
| 网盘自动同步素材 | **不默认使用**。原片上云前必须确认端到端加密且默认关闭（PRINCIPLES §3），且第三方数据保留政策可说明（PIPL 要求，见 [中国法律边界](../10-伦理法律/中国法律边界.md)） |
| 公开仓库 | 不放音视频原片（08 章硬规则）。放的是文档、脚本、脱敏后的衍生数据 |
| 离线优先 | 核心工作流断网可用，联网只做增量同步且需你主动授权（PRINCIPLES §2.2，三步以内可达） |
| 异地副本的另一条路 | 物理硬盘寄回后方 / 交给信任的人，不依赖任何服务政策；缺点是需要时间与签收记录 |
| 含可识别人格的素材 | 未授权即不上传任何第三方。遮蔽与化名的处理方式见 [AI工具链](./AI工具链.md) §2.7，「打码是否足够」按可定位性判定、不按有没有脸见 [中国法律边界](../10-伦理法律/中国法律边界.md) §2 |

## 十一、长期归档：冷存储、格式迁移、以及「能打开」不等于「能还原」

| 动作 | 频率 | 判据 |
|---|---|---|
| 建立冷存副本（离线、不常插电的介质） | 项目结项时 | 至少一份完全离线 |
| 通电抽检 + 哈希复核 | 每年一次 | 不一致即立刻重做，不查原因再拖 |
| 介质迁移 | 每 3–5 年，或介质告警前 | 新旧两份并存到校验通过为止 |
| 接口/文件系统迁移 | 观察到读取设备停产迹象时提前 | 提前一年，不要赌二手市场 |
| 编解码迁移（拍摄格式 → 归档格式） | 只在该格式工具链开始断裂时做 | 迁移必须登记，见 [调色与画面处理](../08-剪辑后期/调色与画面处理.md) 与 08 章处理登记 |
| 保留解码路径证据 | 每次迁移后 | 记录容器、编码、位深、帧率、声道图 |

**「能打开」≠「能还原」**：用播放器拖一遍能看见画面，只证明本机解码器能凑合。真正的还原判据是四项同时成立：**能完整播放到最后一帧；音轨数量与声道映射正确；能回连进工程；哈希与台账一致。** 少一项，都算未通过。

## 常见误区

| 误区 | 代价 | 更正 |
|---|---|---|
| 卡满就地删一点 | 丢掉不可重拍的在场 | 绝对禁区；换卡或当晚倒完 |
| 比文件大小就算拷完 | 静默截断、坏道尾部无人发现 | 比哈希，留清单 |
| 只有一份拷贝 + 一张卡 | 卡坏即素材消失 | 现场版 3-2-1，见第七节 |
| 用 NAS 当备份 | 误删与同步会同时传播 | NAS 是共享存储，不是异地副本 |
| 全上最高码流 | 存储与拷贝时间吃掉拍摄时间 | 格式跟机器与预算走 |
| 不搭代理直接剪高位深 | 每天两小时等待，挤压健康预算 | 当晚批量生成代理 |
| 一场内改帧率 | 抽帧、补帧、音频漂移三重返工 | 基准帧率一场一定，改则登记 |
| 手机素材当固定帧率用 | 长镜头尾音画偏移 | VFR 单独标记与转换后登记 |
| SSD 断电封存多年当归档 | 电荷泄漏导致读不出 | 定期通电校验；用 HDD/磁带做冷存 |
| 相信固态「不会坏」 | 主控一挂全有或全无 | 固态失效不可救性更高 |
| 从不做还原演练 | 出事时发现备份不可用 | 季度演练并记录耗时 |
| 网盘自动同步一切 | 违反数据保留与知情同意边界 | 端到端加密 + 默认关闭 + 逐次授权 |

## 实操要点

- [ ] 出发前确认卡与介质总量按 07 章 ≥2 倍当日时长，且**不在现场格式化旧卡**。
- [ ] 音轨数与容器在开机前按 [收音装备](./收音装备.md) 的通道表设好，不在现场改。
- [ ] 收工 60 分钟内完成现场拷贝，并生成哈希清单、写入台账一行。
- [ ] 当晚批量生成代理；代理不当备份，原片才是资产。
- [ ] 每季度做一次第八节的三项演练，把耗时写进台账；耗时上升就换介质。
- [ ] 每年做一次冷存通电抽检 + 哈希复核；FAIL 立刻重做并保留原记录。
- [ ] 云端同步保持默认关闭；任何一次上云都要能说出保留政策与授权依据。
- [ ] 在台账末尾留一条自检：**今天有没有任何一步，我用了「应该没问题」代替「已校验」。**
