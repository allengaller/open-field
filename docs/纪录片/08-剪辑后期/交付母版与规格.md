# 交付母版与规格

> 交付不是一个文件，是一组各有角色的对象。本篇给出交付件清单、规格反推方法、命名与校验值要求、公开仓库的硬边界——读完你能对电脑上每一份成片回答：它属于哪一层、从谁派生、能否重新生产、别人凭什么信它。

定义先收窄：**母版（master）不是画质最好的那一份，而是所有再生产都从它出发的那一份**。用运维的说法，母版是单一事实源，导出版本是缓存——缓存丢了可以重建，事实源丢了不能。这一篇的全部规则都从这一句推出来。

## 1. 交付件清单

一部片该有的对象，按「失去它的代价」从大到小排【操作性建议】：

| 层 | 对象 | 角色 | 覆盖规则 |
| --- | --- | --- | --- |
| L0 | 归档母版（archival master） | 无字幕干净画面 + 完整混音 + 分轨，最高规格 | 永不覆盖、永不重命名 |
| L1 | 剪辑母版（editing master） | 锁版时间线的成片；调色前/后、混音前/后各留一档 | 同名递进，旧版保留 |
| L2 | 分发版本（distribution version） | 从 L0 一次编码派生，按投放处 | 可覆盖（能重建才允许覆盖） |
| L3 | 平台上传版（upload version） | 某平台某次上传实际提交的字节 | 一次性，命名带投放处代号与日期，不删 |
| S | 字幕文件 | 外挂 `.srt` / `.vtt`，与画面分离 | 随内容版本递进 |
| P | 交付附包（delivery sidecar） | 见 §2 | 只增不改 |

三条硬规定：

1. **L0 必须无字幕。** 字幕烧进母版，日后改一个字就要从调色重做（[字幕与无障碍](./字幕与无障碍.md) §6）。
2. **L0 必须带分轨（stems）。** 对白/环境/音乐三组加全片干净立体声（[混音与终混](./混音与终混.md) §10 第 10 项）。这是「撤回一句话」或「重做配音」时不必重混全片的唯一路径。
3. **工程与依赖同属交付件。** 工程文件、LUT 与调色帧、词表、日志、`OF_REF` 映射一起归档。只留 L0 不留工程，母版就不可复现。

只能留一份时的取舍：

| 情形 | 留什么 | 代价 |
| --- | --- | --- |
| 长期作品的一集 | L0 全套 | — |
| 周更、时间极紧 | 带字幕的最高码率版 + 工程 | 换化名、撤一句、投放处改规格都要回时间线重做 |
| 项目暂停、要换机器 | L0 + 工程 + 原始件位置指针 | 原始件不搬进剪辑目录，只留引用（[素材管理与日志](./素材管理与日志.md) §9） |

## 2. 交付附包里放什么

附包是视频之外那堆「平时没人看、出事时是唯一凭据」的东西。最小集八项：

| 项 | 内容 | 缺了会怎样 |
| --- | --- | --- |
| 授权文书包 | 每条可发布素材对应的授权记录、文书影像、`OF_REF` | 被质疑时拿不出可交付凭证 |
| 排除说明 | 哪些素材因未授权或撤回而未用 | 说不清「没有」和「故意不用」 |
| 更正与联系通道 | 公开一处：事实错误怎么指出、撤回怎么申请 | 只能在评论区被动处理 |
| 素材来源声明 | 拍摄时间范围、地点类型、谁拍的、含哪些第三方素材及其授权状态 | 观众无法判断证据强度 |
| 音乐与二次素材 | 曲目、来源、授权范围、有效期 | 见 [音乐与版权](../04-声音/音乐与版权.md)、[档案与二次素材](../07-拍摄执行/档案与二次素材.md) |
| 处理登记 | 哪些同期段做过降噪/去混响、哪些画面做过修复 | 违反声音侧登记要求（[声音设计](../04-声音/声音设计.md) §9） |
| 双语债记录 | 中文先行、英文欠账与记账位置 | 递延变成事实上的放弃（[../../../PRINCIPLES.md](../../../PRINCIPLES.md) §4） |
| 规格自测记录 | 本版在目标平台真机的检查结论：日期、设备、结论 | 只能凭「上传成功」判断可用 |

撤回与更正的流程细节不在本篇，见 [事实核查与更正](../10-伦理法律/事实核查与更正.md) 与 [知情同意与拍摄授权](../10-伦理法律/知情同意与拍摄授权.md)；权利链自查见 [版权链与E&O](../10-伦理法律/版权链与E&O.md)。交付规格表与清单模板见 [交付规格表](../15-工具与模板/交付规格表.md)。

## 3. 规格：以最终投放处为准反推

不要问「我该用什么码率」，要问「这片子最终在哪里被看到、谁会保存它」。五步反推【操作性建议】：

1. 列出全部投放处：自媒体平台、线下放映、给当事人的核验副本、长期档案。
2. 查每个投放处**当前**的上传说明。不看往年笔记、不看二手总结——说明会变，你的母版不能跟着变。
3. L0 按其中最严的一档留。一次编码的损失不可逆，「先出小的、日后放大」是假命题：插值不会补回细节。
4. 所有派生版本从 L0 一次编码生成，禁止「拿导出版再上传」的转码链。每多一跳，损失叠加且无从归因。
5. 上传后在真机核对（画面、字幕可读性、声音是否需要抬手调音量），而不是只看上传成功的提示。

行业通用档位（【通行共识】，指这些是中间级与分发级的常见选择，不等于某平台「要求」）：

| 用途 | 画面 | 音频 |
| --- | --- | --- |
| 归档母版 / 交付母版 | 10-bit 中间级编码（ProRes 422 HQ、DNxHR HQX 一类）或等价无损编码（FFV1 装在 Matroska 内） | 24-bit PCM WAV，不做有损 |
| 网络分发 | H.264 / H.265，长 GOP | AAC |
| 放映 | 与放映设备一致（分辨率、帧率、色彩范围） | 立体声，交付前做一次单声道合计试听 |
| 当事人核验副本 | 低码率可读即可 | 同上 |

四个容易定错的参数：

- **帧率**：以拍摄帧率为基准，不做帧率转换式交付。素材本身混帧率时，在附包写明哪段被转换、往哪个方向。参数冻结的前提见 [现场工作流与安全](../07-拍摄执行/现场工作流与安全.md) §3。
- **分辨率**：投放处上限封顶，不放大。素材低于投放处规格时按原生分辨率交付并写明原因。
- **场序**：含电视档案的段落必须先做去交织再进时间线处理，否则运动处拉丝；这一步算处理，进附包登记。
- **HDR**：没有确定的投放处就不做 HDR。一份可复现的 SDR 好过两份互相不确定的版本。

响度与码率的具体数值一律现场查、不背：平台会做归一化，交付前按目标投放平台的现行说明核对（[混音与终混](./混音与终混.md) §8）。跨项目复用一组数字是最常见的错误。

## 4. 什么时候把画面与音频分开交付

合并交付是默认，分开交付是给对方留工作余地。四种情况必须分开【操作性建议】：

| 接收方 | 要给的物件 | 为什么不能只给一条成片 |
| --- | --- | --- |
| 放映方 | 无字幕画面版 + 全片 WAV 混音 + 放映设备对应的分辨率与帧率 | 影厅的音量与亮度条件下，成片版的声音常需重新平衡 |
| 译制方或字幕上轨平台 | 无字幕画面版 + 带时码字幕文件（`.srt` / `.vtt`） | 画面里有烧好的字幕，等于让人在错的东西上再改一遍 |
| 愿意复查声音的人 | 三组分轨 + 全片干净立体声 + 工程采样率说明 | 单条混好的声轨无法单独修一句对白 |
| 任何做再加工的下游 | 回批表（XML / EDL 一类）+ 原始件位置指针 | 对方无法定位到原始帧，只能重做 |

其余情况一律合并交付，少一类「两边拿到的东西不一致」的返工。

## 5. 命名与校验值

`PL`（锁版）之后进入交付命名体系，工作版的 `_v03` 递进规则在这里失效。

| 段 | 含义 | 例 |
| --- | --- | --- |
| 项目代号 | 三到四个字母，自定 | `WET` |
| 集号 | `E` + 两位 | `E02` |
| 层 | `L0` / `L1` / `D01` / `SUB` / `PKG` | `L0` |
| 投放处代号 | 自定，**不要写成某平台官方规格名**，避免日后误当作依据 | `UPBZ` |
| 日期 | `YYYYMMDD` | `20260315` |

拼起来：`WET_E02_L0_20260315.mov`、`WET_E02_D01_UPBZ_20260318.mp4`、`WET_E02_SUB_zh_20260315.srt`、`WET_E02_PKG_20260315/`。三条规则：分隔符只用 `_`（不用空格、不用中文、`-` 只出现在段内）；`D01` 之后的名字不再复用；文件名里不出现当事人真名、门牌、车牌、单位名称。

校验值：每个 L0、L1、L3 生成一次 SHA-256，写进 `05_DOC/校验值.md`，并登记进仅可追加的证据日志（[../../../PRINCIPLES.md](../../../PRINCIPLES.md) §2.1；采集侧的固化动作见 [现场工作流与安全](../07-拍摄执行/现场工作流与安全.md) §3）。表头固定五列：

| 文件名 | SHA-256 | 生成时刻 | 派生自（哪版工程、哪步） | 首次投放处与日期 |
| --- | --- | --- | --- | --- |
| `WET_E02_L0_20260315.mov` | `3f9a…`（记全值，不截断） | `2026-03-15 21:40` | `F02` 工程 + 调色第 3 轮 + 终混 `MX02` | B 站 `2026-03-18` |

这张表解决三件事：证明备份没有静默损坏；证明手上这一版就是当时发布的那一版；被人质疑改动时，能拿出「发布态」的指纹。已公开影片的校验值可以放进公开仓库（它只证明同一性，不泄露内容）；**未公开素材的校验值不要公开**——哈希是存在性证明，不必替别人确认某份文件存在过【操作性建议】。

## 6. 公开仓库不放原片

这是硬规则，不是偏好。本仓库是公开仓库，git 历史不会因为你删除文件而忘记它。

| 可以进仓库 | 不可以进仓库 |
| --- | --- |
| 规格表、清单模板、命名示例、日志字段表 | `.mp4` `.mov` `.m4v` `.mkv` `.wav` 等任何画面与声音文件，包括代理和低码率版 |
| 化名编号（`P07-老周`）与不含身份的说明 | 真名与化名的映射、联系方式、门牌、日程 |
| 已公开成片的 SHA-256 | 未公开素材的哈希与任何可下载的原始件链接 |
| 更正与联系通道的文字说明 | 网盘直链、平台原片地址（文档只指向说明性文件） |

依据是事实性的：威胁模型把录音、照片、文档原始件列为第二高敏资产，泄露后果是「言论被溯源、受访者遭报复」（[../../工程/威胁模型.md](../../工程/威胁模型.md) §1），而原始件在磁盘上是明文，前提是整盘加密（同文 §5）。仓库里一次误提交，就把当事人放到了离公开只有一步的地方。

如果确实需要跨地存放母版：加密后再放，密钥与文件分处，并把「放在哪里」写进附包——这条与备份纪律同源（3-2-1 是使用纪律，不是系统能力，见 [../../工程/威胁模型.md](../../工程/威胁模型.md) §5）。

## 7. 内嵌元数据与版权信息

导出时写进文件的字段（容器支持多少写多少，但不依赖它）【操作性建议】：

| 写 | 不写 |
| --- | --- |
| 片名、集号、版本层与日期 | 当事人真名、精确到门牌或经纬度的位置 |
| 版权行（版权人、年份、使用声明） | 你自己的手机号、住址、身份证类信息 |
| 创作者与署名角色 | 未公开的拍摄地点与时间组合 |
| 素材来源声明的公开位置（一处 URL） | 授权文书的具体内容 |
| 联系方式（公开渠道） | — |

不要假定内嵌元数据能活过平台转码：多数平台的再编码会剥离或改写它。所以关键信息一律在附包里另存一份纯文本，元数据只当便利，不当凭据。采集侧记录的 GPS、设备指纹属于证据日志，留在库内，不进导出文件（化名与真名的分离要求见 [../../../PRINCIPLES.md](../../../PRINCIPLES.md) §2.4）。

## 8. 回滚与重制的记录要求

一版被换掉，不是「覆盖发布」这一个动作，而是五条登记。缺一即视为没有记录（【操作性建议】）：

| 项 | 写法 |
| --- | --- |
| 换的原因 | 事实错误 / 撤回 / 授权变化 / 技术问题 / 判断改变（不写「优化」） |
| 被换版本 | 文件名 + SHA-256 + 投放处 + 发布日期 |
| 替代版本 | 新文件名 + 与旧版的差异一句话 |
| 可见的更正 | 更正与联系通道的位置、是否需要单独说明；措辞见 [事实核查与更正](../10-伦理法律/事实核查与更正.md) |
| 失效标记 | 旧版链接保留还是撤下 |

不要静默替换：URL 不变而内容换掉，会让所有引用它的人（包括你自己的笔记与别人的转述）指向一个已不存在的版本。

重制（remake）与回滚不同：重制以 L0 为源，产出一个新的 L0′（新编号、新校验值），旧 L0 不删不覆盖，两者关系写进同一行记录。周更内容被合并进长片属于重制，不是删除。

## 10. 常见误区

| 误区 | 为什么贵 | 改法 |
| --- | --- | --- |
| 「留一个高清成片就够了」 | 高清不是母版；无分轨无工程，任何改动都回时间线 | 按 §1 清单交付 |
| 母版上烧字幕 | 改一个字要重走调色与混音 | L0 干净，字幕外挂 |
| 拿导出版再上传 | 二次转码损失叠加且无法归因 | 一切派生自 L0 |
| 把某平台去年说明当标准 | 平台参数会变，母版规格跟着抖 | 每次交付现查（§3 第 2 步） |
| 母版同名反复覆盖 | 无法证明发布态；备份可能覆盖好版本 | 交付命名不复用 |
| 校验值只存在聊天记录里 | 记录会被清，日志是仅可追加的 | 写进 `05_DOC/校验值.md` 并入日志 |
| 顺手把一段成片传进仓库「做个参考」 | 公开仓库不可撤回，泄的是当事人 | §6 硬规则，提交前跑一遍文件类型检查 |
| 内嵌元数据当凭据 | 平台转码会剥离 | 附包另存纯文本 |
| 悄悄替换旧版 | 引用失效，且像改口 | §8 五项登记 |
| 重制时删旧 L0 省空间 | 失去唯一可对比的历史事实源 | 旧版永不删 |
| 归档只留成片不留工程 | 工程与依赖丢失，母版不可复现 | 工程、LUT、词表、日志同归档 |
| 给放映方一个带字幕的合并文件 | 译制、字幕上轨、音量复核全部做不了 | 按 §4 分轨交付 |

## 实操要点

- [ ] 为本周要发的那一集先建 `05_DOC/校验值.md`，五列表头照 §5 抄，不要等导出完再补。
- [ ] 检查最近一次导出的母版是否带字幕、是否带分轨；若缺，把「L0 = 无字幕 + stems」写进导出模板名称里，让它成为默认。
- [ ] 把交付命名格式（项目代号_集号_层_日期）写进 `05_DOC/`，并给本集所有已存在文件做一次改名映射表——原始素材不参与改名（[素材管理与日志](./素材管理与日志.md) §2）。
- [ ] 在 git 提交前跑一次文件类型检查，确认没有 `.mp4/.mov/.wav/.mkv` 进入暂存区（§6）。
- [ ] 列出本片全部投放处，逐个查当前上传说明，把结论日期写进附包的「规格自测记录」。
- [ ] 给工程、LUT/调色帧、词表、日志、`OF_REF` 映射各指定一个归档位置，并确认它们在 3-2-1 的三份之内。
- [ ] 在附包里补上更正与联系通道的一段文字，公开、可找到、不依赖私信。
- [ ] 把 §9 检查表另存为本集的交付前清单，逐条打勾后才允许上传。
