# 素材管理与日志

> 三 TB 没有日志的素材，等于零素材。它不是资产，是你之后每次工作都要重新支付的债。

本章的地基。拍摄侧的当日入库、三层备份、哈希固化已在 [现场工作流与安全](../07-拍摄执行/现场工作流与安全.md) §3 定死，本篇不重复那些动作，只回答**进入剪辑环节之后，素材如何被找到**。工序阶段见 [粗剪到精剪](./粗剪到精剪.md)，交付物清单见 [交付母版与规格](./交付母版与规格.md)。

## 1. 命题：可检索性决定素材的实际价值

一条素材被用上的概率，约等于它在多长时间内能被你找到。判断标准不是「我大概记得在哪」，而是：

> **三个月后、在另一座城市、电脑冷启动，你能不能在 5 分钟内定位到「他说工资押两个月」的那一句，并确认它有没有授权？**

答不出「是」，那么这条素材在实务上已经不存在。长期跟拍的损失几乎从不发生在拍摄当天，而发生在第十一次拍摄时你找不到第三次的对应段落，于是放弃了这条线。

对 solo 创作者，这件事还有第二层：日志是**你与未来的自己之间唯一的接口**。现场的记忆半衰期极短（[现场工作流与安全](../07-拍摄执行/现场工作流与安全.md) §9 要求当日补场记，理由在此），而剪辑需要的往往是拍摄两周后才浮现的判断。

## 2. 文件夹结构与命名规范

【操作性建议】一套可直接抄用的结构，按「可逆性递减」排列——越靠前的目录越不许动。

```
PROJ_2026-深圳-三号厂/
├── 00_INBOX/            当日拷入，未重命名，清空为目标
├── 01_ORIGINALS/        只进不改：永不重编码、永不改名、永不修图
│   ├── D01/ D02/ ...    按拍摄日
│   │   ├── D03_S12_A_1430.mov      日_场_机位_开始时间
│   │   └── D03_S12_A_1430.mov.sha256.txt
│   ├── AUDIO/           独立录音机文件，D03_S12_REC_1428
│   ├── STILL/           照片（含授权书、文件特写的现场直拍）
│   └── ARCHIVE/         二次素材，权利状态未明的全进这里
├── 02_PROXY/            代理文件，与原始件同名 + _P
├── 03_EDIT/             剪辑工程与自动保存（工程可随便改，素材只放副本）
├── 04_ATMOS/            散文化素材库：空镜与环境声（§7）
├── 05_DOC/              日志、场记、转录、词表、授权索引
└── 06_EXPORT/           输出，全部带版本后缀（§3）
```

命名规则四条【操作性建议】：

1. **原始件的名称只在入库那一刻定一次，此后永久冻结。** 现场工作流已规定 `D03_S12_A_1430`（日_场_机位_开始时间），剪辑侧沿用，不再「为可读性」改名。
2. **版本后缀只出现在派生物上。** `_v03` 属于导出、工程副本、转录稿、日志快照；`01_ORIGINALS/` 里永远没有 `_v`。理由：一旦原始件带上版本后缀，你无法区分「改名」和「被替换」，而哈希记录只对得上一个文件名。
3. 分隔符只用 `_`，字段只用字母数字；不要空格、不要中文、不要日期里的 `-`（不同软件对连字符的排序不一致）。
4. 卷（card/reel）号必须可查：日志里保留「来自哪张卡第几个文件」，因为卡号是恢复现场顺序的最后手段（卡满换卡的节奏本身就是事件顺序的线索）。

场（scene）的编号在拍摄当天不可能穷尽，允许后期追加 `S12b`；不许重排已有编号，因为工程与日志都在引用它。

## 3. 元数据最小集

字段宁少而固定，不要多而漂移。八格，缺一格就是没记（与 [场记表与素材日志](../15-工具与模板/场记表与素材日志.md) 的字段保持一致，剪辑侧多加两格）：

| 字段 | 内容 | 为什么不能省 |
| --- | --- | --- |
| 文件/场次 | `D03_S12_A_1430` | 回到原片的唯一路径 |
| 起止时间码 | 素材内部 TC +  wall clock 开始时刻 | 双系统同步与跨日排序都要 |
| 地点 | 到「哪家」的颗粒：`深圳/白石洲/××旅馆后巷` | 后期「哪个村」会混淆；地名是检索主键 |
| 人物（化名） | 化名编号，见 §6 | 真名不进剪辑侧，见 §8 |
| 授权状态 | 五值枚举，见 §6 | 决定这段能不能出现在导出里 |
| 内容描述 | 一句话：「谁，在做什么，事情有无变化」 | 写不出「变化」的多半是空场 |
| 关键句 + TC | 抄 ≤20 字原话，带 `00:41:12` | 全片最常被回查的一格 |
| 检索关键词 | 3–8 个，取自词表（§5） | 描述给人读，关键词给机器查 |

再加一格「备注/风险」（谁在场可能反对、是否含可识别第三人、是否涉未成年人），这一格直接决定 §6 的处置。

## 4. 日志分级：三级，各算投入产出

不要一次做全。三级分开，各级允许「停在上一级」。

| 级 | 做什么 | 单位时间投入【操作性建议】 | 单位时间产出 | 什么时候停在这一级 |
| --- | --- | --- | --- | --- |
| L1 粗筛 log | 每场一行：内容描述 + 留/废/待看 + 授权状态 | 1 小时素材约 15–25 分钟（配合 3 倍速通读） | 决定「有没有必要看第二遍」 | 素材还没进结构剪时，L1 就够 |
| L2 精筛 select | 给留下来的段落打起止 TC、写关键句、选主条 | 1 小时素材约 60–90 分钟 | 生成「能直接拖上时间线」的候选池 | 单条 5–8 分钟的短片，做到 L2 即可开剪 |
| L3 纸剪引用 | 每场一张卡、八字段，进卡片系统 | 已在纸剪阶段完成，见 [纸剪与结构重组](../05-叙事结构/纸剪与结构重组.md) §3 | 结构比较 | 长片、多集、多线题材才值得做满 |

关键比例：L1 的性价比最高、L2 最容易被跳过、跳过的代价在精剪阶段以十倍工时收回（你在重看第三遍找那句你说得出但找不到的话）。**永远不要因为「急着剪」跳过 L1**——L1 是唯一的、能防止你从最好看的镜头开始剪的机制（[剪辑方法论](./剪辑方法论.md) §9 第一条误区）。

## 5. 词表：让口语、黑话、方言可检索

机器转写在方言与行话上必错（原因见 [字幕与无障碍](./字幕与无障碍.md) §2），错了就搜不到。解法不是「改得更好」，是**建立一张你自己维护的对照表**，放在 `05_DOC/词表.md`【操作性建议】：

| 词 | 常见误转 | 检索别名 | 说明 |
| --- | --- | --- | --- |
| 计件 | 计剑、季件 | piecework | 与「点工」区分 |
| 工段 | 工断 | 工段/车间分组 | 工厂内部编制单位 |
| 押（工资） | 压 | 押薪/欠薪 | 当事人用词，不用「拖欠」替换 |
| 白条 | 白条 | 非正规凭证 | 语义随地区变化，记下说话人所在地点 |

规则三条：

1. **保留当事人的词，不要规范成书面语。** 「押」改成「拖欠」之后，你搜「押」搜不到，而且丢掉了一个说话人（交代方式的取舍见 [冲突悬念与信息节奏](../05-叙事结构/冲突悬念与信息节奏.md) §7）。
2. 每场拍摄前，把可能出现的行话先列 5–10 个进词表；当天转写完立刻补新词。词表比转写软件增值更快。
3. 检索时同时查规范词与别名。工具能力与批量替换的做法见 [AI工具链](../09-技术与设备/AI工具链.md)；机器转写只能帮你找，不能替你判断哪句承重（[纸剪与结构重组](../05-叙事结构/纸剪与结构重组.md) §2 红线）。

## 6. 未授权素材：硬标记 + 导出时自动排除

授权状态只允许五个值【操作性建议】，未知一律按最严的处理：

| 值 | 含义 | 剪辑侧处置 |
| --- | --- | --- |
| `GRANTED` | 有签署文书或明确录音同意 | 正常使用，仍需在附包里能指回凭证 |
| `VERBAL` | 口头同意，未留痕 | 可用但标风险；长片与投稿前补签 |
| `NOTASKED` | 未谈过（公共空间远景、无人脸的空镜） | 可用；出现可识别面部即降级 |
| `DECLINED` | 明确拒绝 | 素材保留，永不进导出 |
| `REVOKED` | 事后撤回 | 立即从所有工程与导出中移除，并记录撤回了哪些版本 |

机制（不要靠自觉）：

- 文件名或目录带硬标记：`..._NOCONSENT` 后缀，或统一放 `01_ORIGINALS/RESTRICTED/`。
- 在剪辑软件里建一个规则 bin：所有 `NOTASKED/DECLINED/REVOKED` 素材放入 `X_不可发布` 分组并**染色**，工程设置里把这个分组设为导出前必须清空的检查项。
- 导出前跑一次「未授权扫描」：用日志（不是眼睛）核对时间线上每个片段的状态字段；`NOTASKED` 里出现可识别面部的，回补同意或删。
- 撤回发生时，日志记三条：撤的是哪一版、该版是否已发布、替代版本是哪一版。流程与措辞见 [知情同意与拍摄授权](../10-伦理法律/知情同意与拍摄授权.md) 与 [事实核查与更正](../10-伦理法律/事实核查与更正.md)。

化名与真名的分离是这套机制的前提：剪辑侧只出现化名编号（`P07-老周`），真名对照表在项目目录之外、加密存放（PRINCIPLES §2.4：真名静态加密、分析层默认只见化名）。

## 7. 散文化素材单独库

空镜、环境声、房间音、天气、交通、无语句的人声——它们不进以「关键句」为主键的日志，因为没有句子可查。单列 `04_ATMOS/`，主键换成两样【操作性建议】：

- **地点 + 时段**（`白石洲/雨后夜`）：散文化素材的功能是空间与时间标记，不是信息。
- **感官描述**（`铁皮雨声 / 排风扇低频 / 远处棋牌室电视`）：用你现场听到的词写，不要写成「环境音-城市」。

采集侧的 20 项清单与「每个地点单独录环境声」见 [空镜与环境影像](../07-拍摄执行/空镜与环境影像.md) §5、§7；房间音的录制要求见 [声音设计](../04-声音/声音设计.md) §4。**这一库最容易被漏记，因为它在拍摄当天看起来「不重要」**，而缺它的那一天，正好是你需要跨段落缝合的那一天。

## 8. 日志与笔记软件的时间戳漂移

田野笔记写在 23:00，说的是 14:30 的事。笔记软件给你的时间戳是**书写时刻**，素材的时间戳是**发生时刻**。两者混在一个字段里，就会发生：你在日志里查到「下午」，回素材发现是早上；或者反过来，你以为某句话有对应素材，其实那天根本没开机器。

解法【操作性建议】：

1. 承认这是两个时钟，永不合并。日志字段固定为「发生时刻（素材 TC / wall clock）」与「记录时刻」两列。
2. 笔记正文里**手写发生时刻**（「14:30 前后，车间门口」），不要依赖软件元数据。
3. 只有 `01_ORIGINALS/` 里带 SHA-256 与可信时间戳的文件可作为「发生时刻」的证据（[../../../PRINCIPLES.md](../../../PRINCIPLES.md) §2.1）；笔记的时间戳永远不作为证据使用。
4. 无法确定发生时刻的素材，标 `TIME-UNCERTAIN`，不许凭推测填时间——填错一次，之后所有引用都错。

## 9. 与 OpenField 证据日志的接口边界

一句话：**OpenField 本地库是证据层，剪辑工程是工作层，中间靠引用编号连接，数据只单向流动（库 → 工程），不回流。**

| 层 | 存什么 | 不存什么 |
| --- | --- | --- |
| OpenField 本地加密库 | 原始文件指针、SHA-256、可信时间戳、GPS、设备指纹、当事人记录、真名与化名映射、授权记录版本 | 剪辑工程、代理文件、导出 |
| 剪辑工程 / 日志表 | `OF-` 引用编号、化名、素材 TC、内容描述、授权状态（从库里抄一次的快照） | 真名、原始文件本体、哈希计算逻辑 |

三条纪律：

- 剪辑侧只放**副本**（代理或导出的工作文件），`01_ORIGINALS/` 的原始件不被工程移动、重命名、重编码。
- 每条日志行留一列 `OF_REF`。引用编号 ↔ 文件名 ↔ 哈希的映射表存在 `05_DOC/`，与库分离；对外发布时可以凭编号回溯到「某一秒」（学术级引用的要求，见 [../../田野方法/08-信效度.md](../../田野方法/08-信效度.md)）。
- 授权状态是**快照**，会过期。开剪前从库里重新拉一次授权状态；工程里那列只是缓存（撤回处置见 §6）。

## 10. solo 的每周 2 小时整理节奏

固定时段，不靠机动【操作性建议】。假设本周素材 2–5 小时（一周拍摄量的常态）。

| 时长 | 动作 | 完成判据 |
| --- | --- | --- |
| 20 分钟 | 清 `00_INBOX/`：重命名、核对哈希与备份份数 | INBOX 为空 |
| 40 分钟 | L1 粗筛：每场一行，标留/废/待看与授权状态 | 本周场次全部有行 |
| 30 分钟 | 转录校正 + 补词表（人名、地名、行话、数字） | 新词 ≥0 条也算完成，但必须确认过 |
| 20 分钟 | 给本周新增空镜/环境声建 `04_ATMOS/` 条目 | 每个新地点至少 1 条 |
| 10 分钟 | 周记三行：本周最重要的素材、最大风险、下周要回查什么 | 写进项目 `05_DOC/周记.md` |

超时处理：任何一周做不到最低 60 分钟（清 INBOX + L1），就把本周的「剪辑」取消。理由与 §1 相同——未整理的素材下周会翻倍变贵。

## 11. 常见误区

| 误区 | 事实 |
| --- | --- |
| 「我记得在哪」 | 三个月后、异地、冷启动时不成立（§1 的判据） |
| 给原始件加 `_v02`、改名成「最终」 | 改名与替换不可区分，哈希失去意义（§3 规则 2） |
| 一次做满 L3 | 前端全做完、后端没开始；L1 每周做，L2/L3 进项目时做 |
| 关键词写成「感人」「重要」「待定」 | 检索词必须是名词（人名、物名、工序名、地名），形容词搜不出来 |
| 把「拖欠」规范掉当事人的「押」 | 丢了检索锚点，也丢了一个说话人（§5） |
| 未授权靠记忆管理 | 记忆在导出那一刻不可靠；要文件名 + 染色 bin + 扫描（§6） |
| 授权状态标一次就完 | 它是快照，会因撤回过期（§6、§9） |
| 空镜不写日志 | 缝合接缝时最缺的就是它（§7） |
| 用笔记软件时间当素材时间 | 两个时钟，永不合并（§8） |
| 把真名写进剪辑日志 | 剪辑工程会随工程文件外流；只放化名与 `OF_REF`（§9） |
| 为了整齐重命名卡号/卷号 | 卡号是事件顺序的最后手段（§2 规则 4） |

## 实操要点

- [ ] 原始件命名一次定死（`D03_S12_A_1430`），`01_ORIGINALS/` 永不改名、永不重编码；`_v03` 只出现在 `06_EXPORT/` 与工程副本上。
- [ ] 每场先做 L1（八格字段 + 留/废/待看 + 授权状态），1 小时素材控制在 25 分钟内；跳级开剪是最贵的错。
- [ ] 维护 `05_DOC/词表.md`：拍摄前列 5–10 个可能行话，转写后立即补录新词，保留当事人用词不书面化。
- [ ] 授权状态用五值枚举，未知即 `NOTASKED`；未授权素材进 `RESTRICTED/` 或加 `_NOCONSENT`，导出前用日志扫描而非肉眼。
- [ ] 散文化素材单建 `04_ATMOS/`，主键是「地点 + 时段 + 感官描述」，每个新地点当天补一条。
- [ ] 日志区分「发生时刻」与「记录时刻」两列；只有带哈希与可信时间戳的原始件可作发生时刻的证据。
- [ ] 与 OpenField 库只单向连接：工程放副本、留 `OF_REF` 编号列；开剪前重新拉一次授权状态。
- [ ] 每周固定 2 小时（20/40/30/20/10 分配）；做不到最低 60 分钟就取消本周剪辑。
