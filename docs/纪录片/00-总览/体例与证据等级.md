# 体例与证据等级

> 本库的写作约定、证据标注规则，以及最重要的一条：哪些话你可以直接用，哪些话你必须自己复核之后再对外用。

这一页不是格式说明，是**责任划分**。本库大量内容涉及法律边界、他人权利、平台规则与事实断言，误用的代价不由本文承担，由使用者承担——所以必须把「我凭什么这么说」写清楚。

## 1. 证据等级

三个标签，含义与 [田野方法库](../../田野方法/README.md) 保持一致，但**本库的分布与那个库不同**，见 §1.3。

| 标签 | 含义 | 你可以怎么用 |
| --- | --- | --- |
| 【核验】 | 编写时通过多源检索逐条比对确认，且给出可指回的来源 | 可直接引用；对外引用前仍建议再点一次来源 |
| 【通行共识】 | 教科书级背景常识（某流派的常识主张、某术语的通用译法、某工序的行业惯例），**编写时未逐条回原文核验** | 可用于理解与决策；进论文、进提案、进对外文案前，回原书原文复核 |
| 【操作性建议】 | 本库自己给出的实践建议，来自可行做法的归纳，不指向某本书的逐字主张 | 直接试用；不适用你的处境就改，但改动要在项目文档里留一行 |

**位置约定**：标签跟在句子或表格行末，或在小节标题后。一段内等级一致时只在段首标一次。表格中作为独立列出现。

### 1.1 一条硬性规则

任何具体数字（时长、dB／LUFS、码率、张数、天数、金额、比例、年限）如果没有标签，视为【操作性建议】，且默认**它不是行业标准，只是本库的一个可用起点**。

本库刻意不给出以下内容的具体数值，因为这类数值由外部权威决定，写死必然过期或错：

| 不给的内容 | 原因 | 去查 |
| --- | --- | --- |
| 平台音频／视频响度与码率目标 | 平台会改，且各平台文档口径不一 | [../04-声音/同期声与收音.md](../04-声音/同期声与收音.md) 只给工作方法，具体值以当期平台文档与交付合同为准 |
| 中国法条条号与罚则 | 修订频繁，误引比不引更危险 | [../10-伦理法律/中国法律边界.md](../10-伦理法律/中国法律边界.md) 只给风险类型与程序，签约与发布前以现行文本与专业人士意见为准 |
| 影展、基金、大赛的届次、奖金、征片日期 | 年年变，且本库编写时未逐项回官网核验 | [../16-学习资源/期刊奖项与基金.md](../16-学习资源/期刊奖项与基金.md) 的当期信息核验法 |
| 书籍出版年、ISBN、中译名 | 转引易错 | [../16-学习资源/书目与教材.md](../16-学习资源/书目与教材.md) 的标注口径 |
| 任何金额、资金额度、家庭开支数字 | 本仓库对家庭财务参数做抽象化处理，不入库 | 一律写「以你自己的试错资金包上限为准」，见 [../../研究/行动总纲.md](../../研究/行动总纲.md) |
| 真实被摄者的姓名、地点、可识别信息 | 公开仓库 | 全库不出现；示例一律用化名编号（`P07-老周`）与可公开的地名 |

### 1.2 【核验】在本库为什么少见

诚实说明：本库主体由写作与自查生成，**没有**经过 [田野方法库](../../田野方法/README.md) 那一轮「并行检索 → 逐条对抗式核验」的流程。因此本库的证据分布是：

- 【操作性建议】占多数——工序、判据、表格、检查项。这部分是本库的主要价值，它不声称外部有依据，只声称可用。
- 【通行共识】次之——理论谱系、历史脉络、术语译法。**这部分风险最高**，因为它读起来像事实。凡是准备写进提案、自述、对外文案的，请回原书或原文复核。
- 【核验】只出现在编写时实际查证过的零星断言上。

反过来，本库对**编造**采取删除策略：编写过程中被删掉的内容包括期刊名、奖项名与届次、奖金数额、片长与集数、票房、出版年、ISBN、若干中文片名，以及若干无法确定归属的历史细节。被删掉的地方留下空缺，而不是补上一个看起来合理的值。所以你在本库看到某处「不给具体数字」时，那是**刻意的**，不是遗漏。

### 1.3 与其他两个库的口径差异

| | 田野方法 | 社会学田野 | 纪录片（本库） |
| --- | --- | --- | --- |
| 主要证据类型 | 文献方法 | 文献＋学术史 | 工序与判据 |
| 【核验】占比 | 高（经一轮对抗式核验） | 中 | 低 |
| 最适合直接用在哪 | 论文方法章节 | 研究与教学 | 现场执行 |

这条差异决定了用法：**不要从本库抄句子到对外文本里；要从本库拿动作到你的拍摄日里。**

## 2. 语言与标注约定

| 项 | 约定 | 例 |
| --- | --- | --- |
| 中文先行 | PRINCIPLES §4：术语用学界通用译法，首次出现括注英文 | 「直接电影（Direct Cinema）」「知情同意（informed consent）」 |
| 括注格式 | 一律「中文（English）」，全角括号，英文内不重复加引号 | 「权利链（chain of title）」 |
| 引号 | 只用「」做引用与术语强调；不用弯引号，不用 '' 或 "" | 「摄影机是世界的副本，不是现实的复制品」 |
| 英文原名保留 | 无通行中译、或中译已失原意时保留英文 | paper edit, chain of custody, vérité |
| 译名分歧 | 两个译法都在用时，正文用主译，首次括注另译 | 「真实电影（Cinéma Vérité，另译真理电影）」 |
| 数字 | 阿拉伯数字；范围用–（半字线）；不写「大约约」 | 15–25 分钟 |
| 时长 | 时:分:秒 写作 `00:41:12`；素材时间码统一 TC | 见 [../08-剪辑后期/素材管理与日志.md](../08-剪辑后期/素材管理与日志.md) |
| 人称 | 对读者用「你」；示例人物用化名编号 | `P07-老周` |
| 语气 | 陈述与判据，不感叹，不煽情，不喊口号 | — |
| 互联网黑话 | 禁用（PRINCIPLES §4 明确拒绝翻译腔与黑话）。此处不列词表：列出来只会被复制成一份可勾选的清单。判据是「这个词能否换成一个具体动作或一条具体判据」，换不成的就是黑话 | 参见 [仓库宪法](../../../PRINCIPLES.md) §4 |
| Emoji | 全文不用，包括表示通过与警告的那几个符号（用文字「是／否」「风险」「必须」代替） | — |

## 3. 文件结构

```
# 中文标题

> 一行引言：这篇解决什么问题，读完你能做什么

（可选）## 0 本篇边界   ← 说明什么不在本篇，避免跨章重述

...分节正文，多用表格：判据表 / 字段表 / 分级表 / 对比表 / 误区表...

## 常见误区           ← 固定收尾节之一

## 实操要点           ← 固定收尾节之二，5–8 条 - [ ] 可执行动作

（可选）## 请复核条目  ← 见 §4

（可选）**相关文档**：… ｜ **最后更新**：YYYY-MM-DD
```

| 节 | 硬性要求 |
| --- | --- |
| 引言 | 一行，说清定位与产出，不写背景铺垫 |
| 表格 | 每篇至少一张判据表或字段表。工序类内容没有表，就无法执行 |
| 常见误区 | 三列：误区 / 为什么错 / 怎么办。「怎么办」必须是动作，不是态度 |
| 实操要点 | `- [ ]` 复选格式，动词开头，可在十分钟内启动其中任何一条 |
| 单篇长度 | 5000–8000 字符。低于此说明没写透，高于此通常说明该拆成两篇 |
| 不重述 | 别处已定义的定义、枚举、数值，一律链接过去。这是本库最重要的编辑约束 |
| 篇尾相关文档 / 最后更新 | **可选**。交叉链接一律走 [知识地图](./知识地图.md) 与本篇 §5 的相对路径规则；靠文末一行手工维护的链接必然过期，因此不设硬性要求。写了「最后更新」的，改动时同批更新 |

## 4. 不确定性如何留在文本里

三档处理方式，按后果严重性选：

| 情况 | 处理 | 例 |
| --- | --- | --- |
| 有分歧，两说都有依据 | 两说并列，给出分歧点，不裁决 | 某流派的创始人归属与起始年份在文献中有不同口径 |
| 本库无法确定 | 明写不确定，放进 `## 请复核条目` | 「该奖项是否仍存续未核验」 |
| 分歧会导致实际风险 | 一律取更保守的一边，并说明为何取保守 | 同意档位、可识别性判断、未成年人处理 |

**`## 请复核条目`** 是本库的一个机制，不是免责声明：编写时明确知道自己没能核验的点，集中列在文件末尾，每条写成可执行的核验动作（查什么、去哪查、什么结果算过关）。读到这一节请当成待办，不要当成已经解决。

已知的待复核条目散落在各章末尾；跨章冲突与待复核项的汇总在 [README](../README.md)。

### 4.1 章间冲突的裁决顺序

本库出现过几次真实的数值/工序冲突（例如电池底线、剪辑休息间隔、分轨组数）。裁决规则：

1. **权威位置优先**：查 [知识地图](./知识地图.md) §3 依赖表。数值以定义处为准（音频＝04，规格＝08，电池与休息＝07）。
2. **更保守者优先**：依赖表未覆盖时，取对被摄者与对证据链更负责的那一边。
3. **明示不一致**：如果两处都合理且无法归一，在较不权威的那一处加一句「本处从宽／从严，判据见 X 章」，不许静默分歧。
4. **有意的收紧不算冲突**：同一规则在不同工序有不同强度（例如一般拍摄的连续工作时长上限长于精剪的），要在文中写明「这是对 X 工序的有意收紧」。
5. 改完在 [README](../README.md) 的更新记录里留一行。

## 常见误区

| 误区 | 为什么错 | 怎么办 |
| --- | --- | --- |
| 把「写得确定」当成「已经核验」 | 本库多数内容是【操作性建议】，语气肯定不等于有出处 | 先看标签，再看 §1.3 |
| 从本库抄句子进提案 | 【通行共识】部分未回原文核验，出处不成立 | 引原书；本库只当导航 |
| 认为没给数字是疏漏 | 是策略：过期或错误的硬数字比空缺更贵 | 见 §1.1 表 |
| 章间冲突时随手挑一个 | 数值散开后无法复核，越用越乱 | §4.1 裁决顺序 |
| 用「差不多」代替标注 | 法律、同意、可识别性上没有中间档 | 不确定时取保守 |
| 看到没有 `## 请复核条目` 就以为全过了 | 待复核项也可能写在正文里 | 全文搜「未核验」 |
| 把黑话当专业 | PRINCIPLES §4 明确拒绝 | 按 §2 禁词表改 |
| 直接改数值以消除不一致 | 可能改错权威侧，把对的改成错的 | 先按 §3 依赖表定位定义处 |

## 实操要点

- [ ] 引用本库任何具体说法前，确认它的标签；【通行共识】回原书复核一次。
- [ ] 把 §1.1「不给的内容」表存进项目文件夹，作为对外文本的自查清单。
- [ ] 本库的过期防线是链接与判据表，不是日期。写了「最后更新」的文件，改动时同批更新；没写的不要为补而补。
- [ ] 遇到本库两处冲突：按 §4.1 顺序处理，并把结论写回较不权威的那一处。
- [ ] 遇到你判断本库写错了（不是不确定，是错）：按 §4 的方式在文本里留一条可执行核验动作，别只删掉。
- [ ] 对外使用（提案、自述、投稿、放映说明）任何事实断言时，自己补上出处，不要引本库当出处。
- [ ] 新建文件时按 §3 骨架写，收尾节名固定为「常见误区」「实操要点」。
- [ ] 发布前跑一次链接检查：全库 `grep` 出相对路径链接，逐个确认目标存在（做法见 [README](../README.md) 的维护节）。
