# P1 收尾与打包分发 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 补齐 P1 最后一块功能（备份恢复 UI 入口），并交付无签名 arm64 macOS 打包链路（DMG + zip 双击可用、全程离线）。

**Architecture:** 备份恢复走既有 `backup:restore` 服务/IPC，只新增窄通道 `backup:pick`（原生文件对话框，路径仅在 main 进程）；打包用 electron-builder 吃 electron-vite 的 `out/` 产物（`@openfield/core` 已被打进 bundle，运行时仅五个 npm 依赖外置），产物 smoke 用 Playwright `_electron` 以 `executablePath` 启动打包后二进制。

**Tech Stack:** Electron 44 + electron-vite 5 + TypeScript + vitest + Playwright `_electron` + electron-builder（实施时 `pnpm add -D electron-builder` 钉最新稳定版到 lockfile）

**Spec:** `docs/规格与计划/规格/2026-09-22-P1收尾与打包分发.md`

## Global Constraints

- 仅 macOS arm64；`mac.identity: null`（无签名，arm64 自动 ad-hoc）
- `appId: fun.meoo.openfield`；`productName: OpenField`
- 不新增任何运行时依赖；唯一新依赖是 devDep `electron-builder`
- renderer 永不接触文件系统：选文件必须经 `backup:pick`（main 进程 `dialog.showOpenDialog`）
- 所有新增通道必须登记进 `apps/desktop/src/shared/ipc.ts` 的 `IPC_CHANNELS`（preload 白名单制）
- `index.html` 的 CSP（`default-src 'self' …`）不得放宽；不得引入任何 CDN/网络资源
- 错误文案映射以规格 §6 为准（`restoreErrorText` 集中一处）
- 测试纪律：TDD；每任务一提交；提交前跑 `pnpm test`（desktop 全量）+ `pnpm typecheck`
- 提交信息体例沿用仓库惯例：`feat(desktop): …` / `test(desktop): …` / `build(desktop): …` / `docs: …`

```ts
import { dirname, join } from 'node:path';
import { fileURLToPath } from 'node:url';
import { expect, test, _electron } from '@playwright/test';

const here = dirname(fileURLToPath(import.meta.url));
const appBinary = join(here, '../release/mac-arm64/OpenField.app/Contents/MacOS/OpenField');

test('打包产物冒烟：窗口出现且能建库（native ABI 闸门）', async () => {
  test.skip(!existsSync(appBinary), '未找到打包产物：先运行 pnpm dist:dir');

  const home = mkdtempSync(join(tmpdir(), 'of-packaged-'));
  const electronApp = await _electron.launch({
    executablePath: appBinary,
    args: [`--openfield-home=${home}`],
  });
  const win = await electronApp.firstWindow();

  try {
    await win.fill('#pass', 'e2e-passphrase-1');
    await win.click('#btn-create');
    await expect(win.locator('#status')).toContainText('"unlocked":true');
  } finally {
    await electronApp.close();
    rmSync(home, { recursive: true, force: true });

});
```

创建 `apps/desktop/src/renderer/src/restore.ts`（纯函数，不 import DOM/electron，node 单测可直接加载）：

```ts
export interface RestoreForm {
  backupPath: string;
  backupPassphrase: string;
  vaultPassphrase: string;
  vaultPassphrase2: string;
}

export function validateRestoreForm(f: RestoreForm): string | null {
  if (!f.backupPath) return '未选择备份文件';
  if (f.backupPassphrase.length < 8) return '备份口令至少 8 个字符';
  if (f.vaultPassphrase.length < 8) return '新库口令至少 8 个字符';
  if (f.vaultPassphrase !== f.vaultPassphrase2) return '两次输入的新库口令不一致';
  return null;
}

/* 服务层原始错误 → 用户文案（规格 §6 映射表，集中于此）。
   备份口令错误在 AES-256-GCM 层表现为 authenticate 失败，与「容器损坏」可区分。 */
export function restoreErrorText(raw: string): string {
  if (raw.includes('拒绝覆盖')) return '当前位置已存在资料库：恢复会替换整个资料库，请先迁移或删除旧库再试';
  if (raw.includes('不是 OpenField 备份文件') || raw.includes('缺少 vault.db') || raw.includes('KDF 参数')) {
    return '备份文件无法读取：可能已损坏';
  }
  if (/authenticat|Unsupported state/i.test(raw)) return '备份口令不正确';
  return raw;
}
```

```ts
import { expect, test, _electron } from '@playwright/test';
import type { ElectronApplication, Page } from '@playwright/test';
import { mkdtempSync, readdirSync, rmSync } from 'node:fs';
import { tmpdir } from 'node:os';
import { dirname, join } from 'node:path';
import { fileURLToPath } from 'node:url';
// electron 包在 Node 环境下 default export 即可执行文件路径；类型层面按 string 用
import electronPath from 'electron';

const here = dirname(fileURLToPath(import.meta.url));

async function launch(home: string): Promise<{ app: ElectronApplication; win: Page }> {
  const app = await _electron.launch({
    args: [join(here, '../out/main/index.js'), `--openfield-home=${home}`],
    executablePath: electronPath as unknown as string,
  });
  return { app, win: await app.firstWindow() };
}

test('P1 恢复闭环：建库→备份→换家恢复→新口令解锁→校验零问题', async () => {
  const homeA = mkdtempSync(join(tmpdir(), 'of-restore-a-'));
  const homeB = mkdtempSync(join(tmpdir(), 'of-restore-b-'));
  try {
    // 家 A：建库 → 登记 → 导出备份
    const a = await launch(homeA);
    await a.win.fill('#pass', 'e2e-passphrase-1');
    await a.win.click('#btn-create');
    await expect(a.win.locator('#status')).toContainText('"unlocked":true');

    await a.win.click('#nav-register');
    await a.win.fill('#ev-id', 'evt-1');
    await a.win.fill('#ev-date', '2026-09-22');
    await a.win.fill('#ev-city', 'KMG');
    await a.win.fill('#ev-loc', '昆明篆新市场');
    await a.win.click('#btn-event');
    await expect(a.win.locator('#status')).toContainText('事件已登记');

    await a.win.click('#nav-overview');
    await a.win.click('#btn-backup');
    await expect(a.win.locator('#status')).toContainText('备份已导出');
    const backupFile = join(homeA, 'backups', readdirSync(join(homeA, 'backups'))[0]);
    await a.app.close();

    // 家 B：无库锁定态 → 恢复。原生对话框无法自动化：main 进程内打桩 showOpenDialog
    const b = await launch(homeB);
    await b.app.evaluate(({ dialog }, file) => {
      (dialog as unknown as { showOpenDialog: unknown }).showOpenDialog = async () => ({
        canceled: false,
        filePaths: [file],
      });
    }, backupFile);

    await b.win.click('#btn-restore');
    await expect(b.win.locator('#restore-fields')).toBeVisible();
    await expect(b.win.locator('#restore-file')).toHaveValue(backupFile);

    // 负例：两次新库口令不一致被前端拦截，不发 IPC
    await b.win.fill('#restore-backup-pass', 'e2e-passphrase-1');
    await b.win.fill('#restore-vault-pass', 'e2e-restored-pass');
    await b.win.fill('#restore-vault-pass2', 'e2e-restored-typo');
    await b.win.click('#btn-restore-run');
    await expect(b.win.locator('#status')).toContainText('两次输入的新库口令不一致');

    // 正例：恢复成功 → 新口令解锁 → 数据与链完整
    await b.win.fill('#restore-vault-pass2', 'e2e-restored-pass');
    await b.win.click('#btn-restore-run');
    await expect(b.win.locator('#status')).toContainText('已从备份恢复');
    await expect(b.win.locator('#restore-fields')).toBeHidden();

    await b.win.fill('#pass', 'e2e-restored-pass');
    await b.win.click('#btn-open');
    await expect(b.win.locator('#status')).toContainText('"unlocked":true');
    await expect(b.win.locator('#stat-events')).toHaveText('1');

    await b.win.click('#nav-verify');
    await b.win.click('#btn-verify');
    await expect(b.win.locator('#report')).toContainText('"chainOk": true');
    await expect(b.win.locator('#report')).toContainText('"issues": []');

    await b.app.close();
  } finally {
    rmSync(homeA, { recursive: true, force: true });
    rmSync(homeB, { recursive: true, force: true });
  }
});
```

> **可见性规则（执行者必读）：** `#btn-restore` 的可见性只随解锁态切换（`applyStatus` 按 `s.unlocked`），与是否 hasVault 无关——恢复成功后（仍锁定）按钮仍可见，因此上例断言的是 `#restore-fields` 收起，而非 `#btn-restore` 隐藏。

````markdown
## 安装与首次打开（macOS）

1. 拿到 `OpenField-<版本>-arm64.dmg`：双击打开，把 OpenField 拖入「应用程序」。
   或拿 `.zip`：解压得到 OpenField.app，自行拖入「应用程序」。
2. 首次打开若提示「无法验证开发者」：**右键点击 OpenField → 打开 → 再点「打开」**（仅需一次）。
   若从浏览器下载的 zip 被拦得更死，可在终端执行 `xattr -d com.apple.quarantine /Applications/OpenField.app` 后再开。
3. 资料库默认存放在 `~/Library/Application Support/OpenField/openfield`；高级场景可用
   `open -a OpenField --args --openfield-home=/path/to/home` 指定其他位置。
4. 全程离线可用：不联网也能创建资料库、导入、登记、校验、备份；「时间同步」是可选增强。

## 从备份恢复

1. 启动后（未创建/未解锁资料库的锁定界面），点「从备份恢复…」，选择 `.ofbackup` 文件。
2. 输入导出备份时设置的**备份口令**，再设置**新库口令**（≥8 字符，两次一致）——恢复后的资料库将改用新口令。
3. 恢复会替换当前位置整个资料库：若该位置已有库，应用会拒绝并提示先迁移或删除旧库。
4. 恢复完成后用新库口令解锁，建议先到「证据链」跑一次校验（应为零问题）。
````
